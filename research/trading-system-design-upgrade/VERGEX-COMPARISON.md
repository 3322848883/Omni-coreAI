# VergeX(nofx) vs OmniAlpha — 逐项对比复核与优化升级

> 2026-10-05 · 目的：**不是复刻 VergeX，而是把它做对的地方「按我们的形态改造」后用来补我们的缺陷**
> 对照材料：`nofx` 源码（`kernel/` `trader/`）+ `findings/F0-nofx.md` + 三份 omnialpha 架构盘点

---

## 〇、先说为什么不能复刻

在逐项对比前必须讲清形态差异——**照抄会做错**：

| 维度 | VergeX (nofx) | OmniAlpha | 对「怎么改造」的影响 |
|---|---|---|---|
| **方向从哪来** | **外部看板**（Claw402.ai Direction Board）给权威方向 | **LLM 自己分析**（含 3 人格讨论） | 它的「状态机镜像提示词」成立的前提是**方向是外部事实**；我们的方向是 LLM 判断，所以状态机**必须放在执行层**（约束「已持仓时能做什么」），不能放在提示词里当规则 |
| **决策者数量** | **单 AI 单决策** | **3 人格讨论 + 融合** | 它的 `enforceVergexSignalPolicy` 改写单一决策；我们要在**融合之后**做状态机过滤，且要考虑「讨论组可能给出互相矛盾的票」 |
| **交易所** | Hyperliquid（`cloid` / `positionTpsl` / dead-man's switch） | **Gate.io**（`auto_size` / `finish_as=position_closed`） | 交易所原生能力不同，**能用交易所解决的就不要自己实现**（我们的 `auto_size` 就是 Gate 独有的礼物） |
| **提示词承载** | **极简**（规则在程序里，提示词只镜像） | **16 条通用契约平铺** | 我们的提示词承载过多——**应该把可程序化的规则从提示词搬进程序**，而不是再加第 17 条 |
| **语言** | 强制英文（丢弃中文分节） | 中文 | 不照抄语言策略（我们的 prompt 与人格都是中文，切换成本高且无收益） |
| **规模** | 单账户、单策略实例 | 数十 bot、多账户、多策略 | 它的「单循环」模型不能直接套我们的多进程模型 |

**结论**：吸收它的**设计原则**（程序强制 / 归属标注 / 不变量 / 能纠正就不拒绝 / 告警接动作），**按我们的形态重写**。

## 一、系统提示词：逐项对比

| # | 维度 | VergeX 怎么做 | OmniAlpha 现状 | 差距 | 优化方案（非复刻） |
|---|---|---|---|---|---|
| P1 | **归属标注** | 分节 `## CODE ENFORCED (cannot be bypassed)` 与 `## AI GUIDED (recommended)`（`engine_prompt.go:530` vs `:565`） | 16 条平铺，无归属 | **缺**：AI 不知道哪些是硬边界、哪些是建议 | 给现有 16 条**打标签**，不是重写。分三类：`[代码强制]`（如 symbol 白名单、SL 必填）、`[代码兜底]`（如名义钳制、保护单对齐）、`[AI 判断]`（如入场标准、信心阈值）。**关键收益**：AI 遇到「代码会兜底」的事不再犹豫（我们已实证过规则 14 的僵局） |
| P2 | **状态机镜像** | `vergexHoldRules()` 逐条对应程序分支（`Flat+bullish → open_long allowed` / `Existing long+bullish → always hold`），注释写明 `mirrors the state machine enforced by the trader` | **无状态机**——规则 14 只管 `flat`、规则 16 只管状态语义，`position_open` + 保护单超额**无规则** | **缺**：AI 只能靠推断，推错了就僵住 | **不照抄它的规则内容**（它的规则依赖外部方向）。我们要的是**一条通用状态规则**：按 `position_state` 分别写明「允许/禁止的动作集」，把「保护单超额该谁管」显式归给引擎 |
| P3 | **输出格式隔离** | XML 标签 `<reasoning>` / `<decision>` + JSON 围栏（`engine_prompt.go:628-667`） | 纯 JSON，CoT 与决策混在 `reasoning_chain` 里 | **缺**：解析要处理「CoT 里出现括号/引号」的情况 | 采用标签契约，但**适配我们的现状**：我们已有 `parse_plan` 从自由文本里抓 JSON，加标签能显著降低解析失败率。**注意**：外部研究显示「先自由推理再约束」（+24pp）优于全程约束 [F3-11]，所以标签方案正合适 |
| P4 | **示例锚定真实值** | JSON 示例内联真实 symbol/杠杆/由 equity 算出的数值，并警告 `Never copy the illustrative example value` | **无示例**，只有 schema 描述 | **缺**：模型对字段语义靠猜 | 在提示词里加一个**用本轮真实数据填充的示例**（symbol、当前权益、算好的名义上限）。这比加规则更有效——「给它一个可照抄的正确答案」 |
| P5 | **自定义的三档模式** | 官方模板 / 模板+自定义 / 完全覆盖（`override_base_prompt`），且**完全覆盖时仍追加 Machine Output Contract** | 人格文件直接替换 system 之外的部分 | **缺**：没有「最小契约」的强制保留 | 我们的 `_SYSTEM_HEAD` 已经承担了这个角色（人格替换不了它）✓ **这条我们已做对**，只需在文档里写明这个边界 |
| P6 | **语言漂移防护** | `englishOnlyPromptSection` 丢弃非英文分节 + 旧 zh 配置整体回退（`engine_prompt.go:295-304`） | 中文，无防护 | **不适用** | **不照抄**。我们的 prompt、人格、注释全是中文，切英文成本高、收益不明。但**可以吸收其思想**：如果未来允许用户自定义 prompt，加一个「语言一致性检查」（中英混排会降低模型理解稳定性） |
| P7 | **提示词回归测试** | 断言必备短语存在、违禁短语不存在、**输出无 CJK**（`engine_prompt_test.go:129-136`） | 无 | **缺**：改提示词无护栏 | 给 `prompt.py` 加**快照式测试**：断言「归属标签存在」「必备规则短语存在」「不含已废弃的措辞」。**去掉 CJK 断言**（我们是中文） |

### 提示词层的优化优先级

| 优先级 | 项 | 成本 | 收益 |
|---|---|---|---|
| **P0** | P1 归属标注 | 低（给现有规则打标签） | 高——直接消除「AI 想做但不敢做」 |
| **P0** | P2 通用状态规则 | 低（新增 1 条） | 高——填补 `position_open` 的规则空白 |
| P1 | P4 示例锚定真实值 | 低 | 中高——减少字段语义误解 |
| P1 | P3 输出格式隔离 | 中（改 prompt + 解析） | 中——降低解析失败率 |
| P2 | P7 回归测试 | 低 | 中——长期护栏 |

## 二、程序执行：逐项对比

### 2.1 它的执行链路（六层过滤管道）

VergeX 的 `runCycle`（`auto_trader_loop.go:19-343`）在**AI 决策与真实下单之间插了六层程序加工**：

```
AI 决策
  ↓ ① filterDecisionsToStrategyUniverse   (:378)  用候选池过滤，丢弃白名单外的标的
  ↓ ② sortDecisionsByPriority             (:754)  先平仓(1) → 开仓(2) → hold/wait(3)
  ↓ ③ isRunning 检查                       (:265)  停止后不再下单（每条决策前再查一次 :294）
  ↓ ④ isSafeMode 过滤                      (:274)  安全模式下**只允许 close/hold**，拦截所有 open
  ↓ ⑤ tradeThrottleReason                 (:316)  节流（反手禁止/冷却/最小持仓）
  ↓ ⑥ executeDecisionWithRecord           (:323)  执行 + 逐条记录成功/失败
  ↓ saveDecision                          (:338)  **即使失败也保存**完整 decision record
```

### 2.2 逐项对比

| # | 维度 | VergeX 怎么做 | OmniAlpha 现状 | 差距 | 优化方案（非复刻） |
|---|---|---|---|---|---|
| E1 | **决策再加工** | 决策进执行前被**程序改写**（状态机 `enforceVergexSignalPolicy`） | **无改写**——AI 输出的 payload 直接落 inbox | **缺**：AI 的判断错误无兜底 | **在 `_execute` 前加一层「状态机过滤」**：按 `position_state` 决定允许的动作集（如 `position_open` 时把 `open_*` 转成 `add_*` 或拒绝）。**适配点**：我们作用于**融合后**的决策，且要处理「讨论组票型矛盾」 |
| E2 | **候选池过滤** | `filterDecisionsToStrategyUniverse` 丢弃不在候选池且非持仓的标的 | 有 `_check_symbol` 白名单（**执行层**） | **部分有**，但粒度是 symbol 级 | 保持现状即可——我们的 `symbols` 白名单已在 executor 强制 ✓ 但**可补**：对「持仓标的的平仓」放行（现在 `_check_symbol` 一视同仁） |
| E3 | **先平后开排序** | `close_*`=1 / `open_*`=2 / `hold,wait`=3 | **无排序**——信号里多腿按数组顺序执行 | **缺** | 在 executor 处理 `orders[]` 多腿时**按动作排序**。我们的多腿信号确实存在（网格、多 TP） |
| E4 | **停止检查点** | 每轮开始时 + **每条决策执行前**都查 `isRunning`（`:265`、`:294`） | 有 PidLock，但**执行中无中断检查** | **缺**：长批次执行中无法立即停手 | 在 `watcher.process_file` 的每条 intent 之间加「停止标志」检查（优雅停机） |
| E5 | **安全模式** | 连续 3 次 AI 失败 → 只允许 close/hold，**恢复后自动退出**（`:215`、`:274`） | 只有 `error_streak` 告警，**无降级动作** | **缺** | 在 `plan` 侧加：连续失败 N 次 → 人格只允许 hold/close/reduce/modify。**适配点**：我们的「AI 失败」要包含「解析失败」「LLM 超时」「工具循环超限」三类 |
| E6 | **节流/冷却** | 反手禁止、平仓后 4h 冷却、最小持仓 90m、噪声区不主动平仓（但止损/大盈利可绕过） | **无** | **缺** | 引入**节流层**，但**阈值要按 Gate 品种重新标定**（它的 4h/90m 是针对美股/加密的特定回放结果，不能照抄）。建议先只做「反手禁止」（最安全、收益最明确） |
| E7 | **开仓后强制保护** | `SetStopLoss` 失败 → `closeUnprotectedPosition` 立刻平掉；回滚走 `emergencyClosePositionAndVerify`（3 次重试 → `CancelAllOrders` → `GetOpenOrders` 复查） | 有 `_precheck_exit_triggers`（**但 `_stop_entry` 没调**），**无「挂失败即回滚」** | **缺两块** | ① `_stop_entry` 补 precheck（几行）② 挂保护失败时回滚。**适配点**：我们已有 `_rollback_unprotected_entry`，约定是「未成交则撤单、已成交只告警」——**沿用，不要改成自动市价平仓** |
| E8 | **保护单形态** | Hyperliquid 用 `grouping=positionTpsl`（仓位级分组） | 我们每轮挂**独立**的 TP/SL，带显式张数 | **缺** | **用 Gate 的原生能力**：`close=true, size=0` / `auto_size=close_long\|close_short`（这是 Gate 独有、Hyperliquid 没有的），让保护单语义变成「平掉全部」，**从根上消除张数对齐问题**。**必须先实测** `price_orders` 是否接受该字段 |
| E9 | **孤儿/陈旧单清理** | 平仓后 `CancelAllOrders` + `GetOpenOrders` 复查；`submission_recovery_policy` 保留未确认提交；broad cancel-all 即使本地无匹配也路由到交易所 | 有孤儿扫描（撤孤儿保护单），**但不含「入场单被撤 → 连带撤其保护单」** | **部分有** | 补「入场单幂等」：撤旧入场单时连带撤同批保护单。**适配点**：Gate 的 `text` 有 28 字节 + 字符集约束，批次标记要用短后缀 |
| E10 | **对账** | 启动时 fail-closed（缺报告 ≠ 空仓）、运行期「近期活动宽限窗 + 单笔定向查询」、模糊在途命令**故意保持未决** | `reconcile_protection` **只告警、零调用** | **完全缺** | 新增对账循环。**适配点**：我们规模小，用「启动时 + 每 N 分钟 + 开仓前轻量校验」即可，不需要它的毫秒级事件驱动 |
| E11 | **仓位定量** | 程序算（`accountEquity × ratio`）+ 校验 + 杠杆自动夹 | **已有**（`_align_size_to_risk` + `_check_notional` + 名义钳制） | **✅ 我们已做对** | 保持。可补它的两个细节：① 保证金不足时缩到 `maxAffordable×0.98`（留手续费缓冲）② 缩减后的部分仓位不低于正常 stake 的某比例（避免交易所拒单） |
| E12 | **独立回撤保护** | 独立线程：盈利 >5% 后从峰值回吐 40% 即平仓，**用价格基而非保证金基** | 只有 `daily_loss_limit_usd`（按 bot 落盘） | **缺** | 加**账户级**回撤保护（不是 bot 级）。**适配点**：它用价格基的理由是「高杠杆下保证金基阈值会被动收紧」——我们 50x 杠杆下这个理由更强 |
| E13 | **完整留痕** | `DecisionRecord` 存 system/user prompt + CoT + 原始响应 + 逐条执行日志，**即使失败也保存** | thinking 截断（`content_head` 500 字）、**讨论轮完全不落盘** | **缺** | 去掉截断 + 讨论轮落盘。**适配点**：我们是每轮一个 `thinking.json`，可保留该结构，只补「讨论轮的调用」与「完整正文」 |
| E14 | **健康暴露** | `GetStatus` 输出 `safe_mode` / `ai_wallet_status`，面板直接显示 | 健康拆两文件、`status` 不暴露健康 | **缺** | 合并健康视图 + `status` 暴露关键态（含 `safe_mode` 等价物） |

## 三、针对我们缺陷的优化清单（按「补哪个缺陷」组织）

| 我们的缺陷 | VergeX 的对应做法 | 优化方案 | 为什么不直接复刻 |
|---|---|---|---|
| **`_stop_entry` 绕过账户级风控** | 两条入场路径都过 `validateDecisions` | 补 `_check_open_sl` + `_check_account_risk` | 无差异，可直接对齐 |
| **保护单张数 vs 持仓脱钩** | Hyperliquid `grouping=positionTpsl` | 用 Gate 的 `auto_size=close_long\|close_short` | **交易所能力不同**——Gate 的方案比 Hyperliquid 更彻底（它连「张数」都不需要） |
| **无状态机，AI 判断无兜底** | `applyVergexSignalPolicy` 改写决策 | 在融合后加状态机过滤层 | **方向来源不同**——它的方向是外部事实，我们的来自 LLM，所以状态机只能约束「已持仓时允许什么」，不能替 AI 决定方向 |
| **规则 14 僵局（AI 想做不敢做）** | 提示词标注 `CODE ENFORCED` vs `AI GUIDED` | 给 16 条规则打归属标签 | 无差异，可直接对齐 |
| **告警不接动作** | 安全模式自动进入/退出 | 给高风险告警配默认动作 | 无差异 |
| **9 份状态副本无权威** | 交易所为权威 + 对账 fail-closed | 声明权威 + 新增对账 | **规模不同**——它毫秒级事件驱动，我们周期对账够用 |
| **无幂等** | venue `trade_id` + 确定性 ID 去重 | `client_order_id` 跨日唯一 | 无差异 |
| **无节流** | 反手禁止/4h 冷却/90m 最小持仓 | 先只做反手禁止 | **阈值不能照抄**——它的数值来自美股/加密的特定回放，需按 Gate 品种重新标定 |
| **无账户级风控** | `available_capital` 多 bot 分配额度 | 新增账户级配置 + 合并闸门 | **形态不同**——它是单账户单实例，我们是多 bot 共享账户，需要跨进程的合并口径 |

## 四、明确不做的（避免「为了对齐而对齐」）

1. **不切英文提示词**（P6）——成本高、收益不明，且我们的人格与文档全中文。
2. **不照抄节流阈值**（E6）——它的 4h 冷却 / 90m 最小持仓是特定品种回放结果，直接套用会误伤。
3. **不引入它的「外部看板」前提**——我们走的是 LLM 自主分析路线，这是产品定位差异，不是缺陷。
4. **不把状态机放进提示词**——方向来自 LLM 时，提示词里的状态机只是劝告；必须在执行层强制。
5. **不做毫秒级对账**——规模不匹配。

---

## 五、一句话总结

VergeX 最值得学的不是某个具体机制，而是**它把「程序能保证的事」和「LLM 必须说的事」分得很干净**：

- **程序保证**：状态机、仓位定量、保护单形态、对账、幂等、节流、安全模式
- **LLM 说**：方向、理由、止损结构

我们的缺陷几乎全在「程序保证」那一侧——**提示词写了 16 条，但执行层缺了对应的强制**。所以升级方向不是「再加规则」，而是**把可程序化的规则从提示词搬进程序，提示词只保留「AI 必须知道的」并标注归属**。
