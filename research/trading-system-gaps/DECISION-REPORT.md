# 功能缺口逐条核实报告 — 做 / 不做 / 为什么

> 日期: 2026-09-28 | 原则: 真升级才做，反向升级/无必要坚决不做

---

## 评估标准

| 维度 | 含义 |
|------|------|
| **建议** | ✅ 先做 / ⚠️ 可做可不做 / ❌ 不做 |
| **升级 vs 反向** | 反向 = 增加复杂度但不增加价值，甚至引入新风险 |
| **难度** | 低（<2天）/ 中（3-5天）/ 高（1-2周+） |
| **依赖** | 需要先做什么 |

---

## P0 系列

### ① 组合级风控 — ❌ 不做（你的设计意图已正确）

**你的话**：「多 BOT 模式一个整体做风控，因为总共相当于共同管理一个仓位」

**核实**：✅ **完全正确，不做**

多人格共管的融合后信号已经过 source_bot 的风控（min_confidence/max_notional/require_sl）。本质是**一个仓位的联合决策**，不是多个独立仓位。组合级风控（相关性/集中度/跨品种敞口）是**对冲基金 21 个独立策略各跑各的**才需要的。

**如果做了会怎样**：加一层"组合审批"延迟执行、加配置复杂度、在单品种场景下**永远触发不了相关性检查**——纯增加负担。

---

### ② 回测验证体系 — ✅ 先做（P0 最高优先级）

**需要做什么**：
1. LLM 策略回测框架（prompt 固化→逐 bar 模拟→绩效）
2. DSR + p-value 统计显著性
3. vs Buy&Hold + vs sma(50,200) 基准
4. IS→WFA→OOS 三段协议

**为什么要做**：
- 40 个 LLM 策略**仅 2 个跑赢 Buy&Hold** [F2-6]——没有回测我们**不知道自己的策略是否真有 alpha**
- 现在 21 个人格全靠"看着感觉对"选 prompt，无法量化比较
- 你已经在用 metrics 记分板——缺的就是统计显著性那一环

**怎么做**：
```
gate_bot/backtest/
├── llm_snapshot.py     # 每轮 Plan 结果存快照（decision + reasoning + snapshot_digest）
├── replay.py           # 回放历史快照→逐 bar 模拟→出绩效
├── stats.py            # DSR / p-value / Sharpe / MaxDD
└── report.py           # vs B&H / vs sma 基准对比
```
核心：**不需要重新跑 LLM**——journal 里已经有每轮决策+市场快照，直接回放即可。

**难度**：中（3-5 天）。journal 数据已齐全，缺的是回放引擎和统计计算。

**升级 vs 反向**：**真升级**——从"盲跑"到"知道策略是否有效"。

**风险**：如果回测显示策略没 alpha，可能"不愉快"——但**这是好事**（避免真金白银亏）。

---

### ③ 策略衰减检测 — ✅ 先做（紧跟回测）

**需要做什么**：
1. 滚动窗口指标（30d Sharpe / 胜率 / 回撤）写入 `health.json`
2. 衰减告警（滚动指标跌破历史 50% → 告警）
3. 可选：自动切 paper

**为什么要做**：
- 策略失效是**必然的**——被复制→资金涌入→alpha 被吃掉 [F5-4]
- 我们跑 21 个 bot 7×24，**现在完全看不到哪个在衰减**
- 实盘 4 个月击穿历史最大回撤是常见信号 [F5-4]——不监控就是在裸奔

**怎么做**：
```python
# 每轮 PlanRunner 后追加（轻量）
data/bots/<id>/state/perf_metrics.jsonl
  {ts, rolling_sharpe_30d, win_rate, max_dd_30d}

# 告警（本地日志+可选钉钉）
if rolling_sharpe < 0.5 * historical_sharpe:
    log_warning("策略衰减: {bot_id}")
```

**难度**：低（1-2 天）。journal 有全部决策+结果数据，只加计算和告警。

**升级 vs 反向**：**真升级**——从"不知道何时停"到"衰减即知"。

---

### ④ 订单状态机补全 — ✅ 先做（基础可靠性）

**需要做什么**：
1. 补终态：`mmp_canceled`（市价保护自动撤单）
2. 部分成交处理：IOC 部分成交后 `accFillSz ≠ 0` 的正确记录
3. 改单状态管理：OKX 不支持原地改 TP/SL，需撤旧挂新

**为什么要做**：
- 部分成交是最常见的"意外状态"——不处理会导致**仓位记录与实际不一致**
- `mmp_canceled` 不识别会**丢失订单**
- 这是**数据完整性**问题，不是锦上添花

**怎么做**：
```python
# schema.py
ORDER_FINAL_STATES = {"filled", "canceled", "mmp_canceled"}
PARTIAL_FILL_POLICY = "wait"  # 或 "cancel_rest"

# executor.py
if state == "mmp_canceled":
    log_warning("市价保护自动撤单")
    archive_signal(order_id, reason="mmp_canceled")
```

**难度**：低（1-2 天）。主要是分支判断和日志记录。

**升级 vs 反向**：**真升级**——数据完整性是可靠性的基础。

## P1 系列

### ⑤ TWAP/滑点保护 — ⚠️ 可做可不做

**需要做什么**：大单拆 TWAP + 市价单 `slippagePct` 硬保护

**为什么可不做**：
- 我们 `max_notional_usd: 3000`，单笔 3000 USDT 对 BTC 流动性**冲击微乎其微**
- TWAP 主要是**机构千万级大单**的需求
- 但 `slippagePct` 值得加（一行代码的事，OKX 原生支持）

**如果做**：只加 `slippagePct: 0.01` 默认值（低难度），TWAP 不做。

**升级 vs 反向**：滑点保护 = 真升级；TWAP = 过度工程（反向升级）。

---

### ⑥ self-critique 信念更新 — ⚠️ 可做可不做

**需要做什么**：平仓后 LLM 自我批判→提炼投资信念→存 Profile

**为什么可不做**：
- 我们已有 4 层记忆（journal 记 reasoning、profile 记统计）
- FinCon 的"信念更新"是**强化学习替代品**——我们的策略是 prompt 规则型，不需要学习
- 加了反而多一次 LLM 调用（成本+延迟）

**如果做**：平仓后一次 self-critique 调用，信念存 `lessons[]`，进 system prompt。

**升级 vs 反向**：**边界**——短期看是反向（多花钱多复杂度），长期看如果策略需要"越跑越好"则有价值。

**建议**：先不做。等回测显示策略需要优化时再考虑。

---

### ⑦ 监控告警 — ✅ 做（但简化版）

**需要做什么**：延迟/成交率/滑点/进程存活 → 日志告警

**为什么要做**：
- **silent failure 是致命的**——行情源断了但进程还在跑 [F5-1]
- 我们 7×24 跑 21 个 bot，**需要知道哪个出问题了**

**怎么做**（简化版，不做 Kafka/Flink）：
```python
# 每轮写 health.json
{ts, llm_latency, exec_latency, error_count, last_heartbeat}

# 告警规则
if error_count > 5 or last_heartbeat > 600:
    log_error("bot 异常")  # 可选钉钉
```

**难度**：低（1 天）。只加日志和阈值判断，**不做**全链路监控栈。

**升级 vs 反向**：简化版 = 真升级；完整 Kafka/Flink 栈 = 反向（过度工程）。

---

### ⑧ 策略评分 — ⚠️ 可做可不做

**需要做什么**：DSR/p-value/多维评分集成到 metrics

**为什么可不做**：
- 如果做了②回测，评分是回测的**副产品**
- 独立做评分框架是重复建设

**如果做**：②做完后在 metrics 加 DSR 计算即可。

**升级 vs 反向**：依赖②，单独做 = 反向。

---

### ⑨ 仓位管理（波动率目标）— ✅ 做（简单版）

**需要做什么**：按 ATR 波动率动态调整 size_usd

**为什么要做**：
- 波动率目标是**性价比最高**的仓位缩放 [F4-7]
- 现在固定 size_usd，BTC 波动 3% 和 1% 时仓位一样——**波动大时风险暴增**

**怎么做**：
```python
# sizing.py
vol_ratio = target_atr_pct / current_atr_pct
size_adjusted = base_size * clamp(vol_ratio, 0.5, 2.0)
```

**难度**：低（半天）。一行公式。

**升级 vs 反向**：**真升级**——同样的仓位在不同波动下风险一致。

---

### ⑩ 交易所限频管理 — ⚠️ 可做可不做

**需要做什么**：跟踪 API 调用频率，接近限频时降速

**为什么可不做**：
- 6 个 bot 每 15 分钟一次调用 = **每小时 24 次**，远低于任何交易所限频（通常每秒 20+ 次）
- 只有 21 个 bot **同时在同一秒调用**才会撞限频
- 实际上 persona-run 是串行的，天然限速

**如果做**：在 gate_client 加一个简单的调用计数器即可。

**升级 vs 反向**：**反向**（过度工程）——当前调用量远达不到限频阈值。

## P2 系列

### ⑪ 多模态（K 线图识别）— ❌ 不做

**为什么不做**：
- 需要 VLM 能力 + 图像生成管道 + 成本高
- 我们已有 SMC 工具（smc_map/smc_events）覆盖结构分析
- K 线形态识别是**锦上添花**，不是核心需求

**升级 vs 反向**：**反向**——大量复杂度换取少量信息增量。

---

### ⑫ 在线自适应重训 — ❌ 不做

**为什么不做**：
- "prompt 参数"在我们系统中是**策略人格**（固定 prompt 文件），不是可训练参数
- FreqAI 的重训是 ML 模型（权重更新），我们是 LLM 提示词——**本质不同**
- 如果要"优化 prompt"，那是一个新功能（prompt 优化器），不是重训

**升级 vs 反向**：**反向**——概念错配，增加复杂度不解决问题。

---

### ⑬ DCA/COMBO bot — ⚠️ 可做可不做

**为什么可不做**：
- DCA 是机械策略，不需要 LLM
- 我们的 LLM 策略已覆盖趋势/震荡/突破
- 但如果用户想跑 DCA，现在可以用 grid 近似

**如果做**：在 executor 加 DCA 定时加仓逻辑。

**升级 vs 反向**：边界。做 = 功能扩展（中性），不做 = 保持聚焦。

---

### ⑭ 交易日志/复盘 — ⚠️ 可做可不做

**为什么可不做**：
- journal 数据已完整（决策+理由+时间戳+结果）
- 只差前端展示（HTML/网页）
- 核心数据不缺

**如果做**：一个简单 HTML 报告生成脚本。

**升级 vs 反向**：中性（不加不减），做 = 提升体验。

---

### ⑮ 组合再平衡 — ❌ 不做

**为什么不做**：
- 依赖⑧策略评分（还没做）
- 21 个 bot 各 5000 资金，规模小，再平衡收益微乎其微
- 复杂度高（资金转移、仓位同步、中断处理）

**升级 vs 反向**：**反向**——高复杂度低收益。

---

### ⑯ A/B 测试 — ⚠️ 可做可不做

**为什么可不做**：
- 依赖②回测和⑧评分
- 单用户场景下"人脑对比"够用（看 metrics 记分板）
- 21 个 persona 已经是"天然 A/B"（不同策略并行跑）

**升级 vs 反向**：边界。21 persona 已有 A/B 效果。

---

### ⑰ 防 MEV/防夹 — ❌ 不做

**为什么不做**：
- 我们主要跑 CEX（Gate/OKX/Binance 等），CEX 无 MEV
- DEX 场景（Hummingbot）暂无需求
- 需要 Flashbots/私有路由基础设施

**升级 vs 反向**：**反向**——为不存在的问题增加复杂度。

---

### ⑱ 快/深思考混合 — ❌ 不做

**为什么不做**：
- DeepSeek-flash 已经很便宜（$0.15/M token）
- 混合模型增加配置复杂度（两套 API key、两套 prompt 模板）
- 每轮成本差 < $0.01，不值得

**升级 vs 反向**：**反向**——成本节省微乎其微，复杂度显著增加。

## 最终建议：只做 5 件事

| 优先级 | 功能 | 工作量 | 效果 |
|--------|------|--------|------|
| **1** | ② 回测验证 | 3-5 天 | 知道策略是否真有 alpha |
| **2** | ③ 衰减检测 | 1-2 天 | 知道何时该停 |
| **3** | ④ 订单状态机 | 1-2 天 | 数据完整性 |
| **4** | ⑦ 监控告警（简化版） | 1 天 | 知道哪个 bot 出问题 |
| **5** | ⑨ 波动率仓位 | 半天 | 风险一致性 |

**总计约 7-10 天工作量。其他 13 项坚决不做或缓做。**

**核心原则**：我们是**单人交易者 + 21 个 prompt 策略**，不是对冲基金。每加一个功能都要问：**这真的让我更赚钱/更安全吗？还是只是看起来更专业？**
