# F2: Model Context Protocol (MCP) 官方规范与工程实践

## Findings

### [1] MCP 采用 host-client-server 三层架构，基于 JSON-RPC 2.0 有状态会话，每个 client 与一个 server 保持 1:1 隔离连接，host 负责安全边界与上下文聚合
- quote: "The Model Context Protocol (MCP) follows a client-host-server architecture where each host can run multiple client instances. ... A host application creates and manages multiple clients, with each client having a 1:1 relationship with a particular server."
- url: https://modelcontextprotocol.io/specification/2025-06-18/architecture
- source_type: primary
- published: 2025-06-18
- confidence: high

### [2] MCP 三类服务端原语按控制权分层：Prompts 为用户控制（slash commands）、Resources 为应用控制（文件/git 历史）、Tools 为模型控制（API 调用、文件写入）
- quote: "Prompts | User-controlled | Interactive templates invoked by user choice ... Resources | Application-controlled | Contextual data attached and managed by the client ... Tools | Model-controlled | Functions exposed to the LLM to take actions"
- url: https://modelcontextprotocol.io/specification/2025-06-18/server
- source_type: primary
- published: 2025-06-18
- confidence: high

### [3] 规范版本演进时间线：2024-11-05（初版）→ 2025-03-26（Streamable HTTP、OAuth）→ 2025-06-18（结构化输出、tool annotations）→ 2025-11-25（icons、URL elicitation、experimental tasks）→ 2026-07-28（无状态重构），另有 draft 持续演进
- quote: "Specification: 2026-07-28 ... 2025-11-25 ... 2025-06-18 ... 2025-03-26 ... 2024-11-05 ... draft"
- url: https://modelcontextprotocol.io/llms.txt
- source_type: primary
- published: 2026-07-28
- confidence: high

### [4] 2026-07-28 版本重大重构为无状态协议：移除 initialize 握手与 Mcp-Session-Id，每请求在 _meta 携带协议版本/客户端能力/clientInfo，版本不匹配返回 UnsupportedProtocolVersionError（-32022）
- quote: "Make MCP stateless: remove the `initialize`/`notifications/initialized` handshake. Every request now carries its protocol version and client capabilities in `_meta` (`io.modelcontextprotocol/protocolVersion`, `io.modelcontextprotocol/clientCapabilities`). ... Version mismatches return `UnsupportedProtocolVersionError`"
- url: https://modelcontextprotocol.io/specification/2026-07-28/changelog.md
- source_type: primary
- published: 2026-07-28
- confidence: high

### [5] Tool 定义包含 name/title/description/inputSchema（JSON Schema）/outputSchema（可选）/annotations；工具结果分 unstructured content（text/image/audio/resource_link）与 structuredContent，错误分协议错误（JSON-RPC error）与工具执行错误（isError: true）
- quote: "A tool definition includes: `name`: Unique identifier for the tool ... `inputSchema`: JSON Schema defining expected parameters ... `outputSchema`: Optional JSON Schema defining expected output structure ... Tool Execution Errors: Reported in tool results with `isError: true`"
- url: https://modelcontextprotocol.io/specification/2025-06-18/server/tools
- source_type: primary
- published: 2025-06-18
- confidence: high

### [6] 可靠性机制：所有请求 SHOULD 设置超时并在超时后发送 cancellation；progress notification 可重置超时时钟但必须有最大超时上限；Streamable HTTP 中关闭 SSE 响应流即视为取消；2026-07-28 起不再支持 SSE 断线重续（Last-Event-ID），断流须以新 request ID 重发
- quote: "Implementations SHOULD establish timeouts for all sent requests... When the request has not received a success or error response within the timeout period, the sender SHOULD issue a cancellation notification... implementations SHOULD always enforce a maximum timeout... Closing the SSE response stream MUST be treated by the server as cancellation of that request. ... Remove SSE stream resumability and message redelivery... clients MUST re-issue it as a new request with a new request ID"
- url: https://modelcontextprotocol.io/specification/2025-06-18/basic/lifecycle
- source_type: primary
- published: 2025-06-18
- confidence: high

### [7] 安全模型四原则：用户同意与控制、数据隐私（host 须获明确同意才暴露数据）、工具安全（annotations 不可信、须人工确认）、LLM Sampling 控制；工具描述/annotations 视为不可信输入除非来自可信 server
- quote: "Users must explicitly consent to and understand all data access and operations... Tools represent arbitrary code execution and must be treated with appropriate caution. In particular, descriptions of tool behavior such as annotations should be considered untrusted, unless obtained from a trusted server. Hosts must obtain explicit user consent before invoking any tool"
- url: https://modelcontextprotocol.io/specification/2025-06-18/index
- source_type: primary
- published: 2025-06-18
- confidence: high

### [8] 授权采用 OAuth 2.1：安全最佳实践明确定义 confused deputy、token passthrough（禁止）、SSRF、state handle 劫持、本地 server 供应链攻击、OAuth URL 注入（javascript:/shell injection）、mix-up 攻击等威胁模型及缓解措施（per-client consent、audience 校验、私网 IP 阻断、沙箱隔离）
- quote: "\"Token passthrough\" is an anti-pattern where an MCP server accepts tokens from an MCP client without validating that the tokens were properly issued *to the MCP server*... MCP servers MUST NOT accept any tokens that were not explicitly issued for the MCP server. ... If an MCP client supports one-click local MCP server configuration, it MUST implement proper consent mechanisms prior to executing commands."
- url: https://modelcontextprotocol.io/docs/2026-07-28/tutorials/security/security_best_practices.md
- source_type: primary
- published: 2026-07-28
- confidence: high

### [9] 官方 Skills 扩展（io.modelcontextprotocol/skills，SEP-2640 Final）让 MCP server 暴露 Agent Skills：skills/list + skills/get + resources/read 读取 SKILL.md；每个 skill 须含 YAML frontmatter（name/description）与完整文件 manifest（URI + SHA-256 digest + size），host 必须校验 digest 与 frontmatter，批准绑定到 manifest 变更即撤销；建议每 skill 不超 512 文件 / 16 MiB
- quote: "A skill is a directory containing a `SKILL.md` file and optional supporting files, following the Agent Skills specification. ... A manifest MUST include `SKILL.md` and every supporting file, with each file's URI, SHA-256 digest, and byte size. ... Hosts MUST NOT use content that fails verification. ... Servers SHOULD NOT exceed 512 files or 16 MiB per skill"
- url: https://modelcontextprotocol.io/extensions/skills/overview.md
- source_type: primary
- published: 2026-07-28
- confidence: high

### [10] 版本协商区分 Modern（2026-07-28+，per-request _meta）与 Legacy（2025-11-25 及更早，initialize 握手）两个 era；dual-era 实现须支持双向互操作，server/discover 可用于探测；扩展通过 capabilities.extensions 字段以 `io.modelcontextprotocol/*` 前缀标识协商
- quote: "Modern: protocol versions that convey version, identity, and capabilities as per-request metadata (revision `2026-07-28` and later). Legacy: protocol versions that establish a session with an `initialize` handshake (`2025-11-25` and earlier). Dual-era: an implementation that supports both modern and legacy versions."
- url: https://modelcontextprotocol.io/specification/2026-07-28/basic/versioning.md
- source_type: primary
- published: 2026-07-28
- confidence: high

### [11] 大规模工具管理的官方推荐模式是 progressive discovery（search_tools → get_tool_details → execute 三层）与 programmatic tool calling / code mode（模型写脚本在沙箱中组合工具调用，仅最终结果回模型），配合 outputSchema 自动生成类型化 API；宿主可按 skill 声明动态连接/断开 MCP server
- quote: "Progressive discovery avoids this: The host fetches tool definitions via `tools/list` as normal, but defers injecting them into the model's context. The host provides a lightweight `search_tools` meta-tool... Programmatic tool calling (sometimes called \"code mode\") provides a way for clients to compose tool calls effectively. Instead of calling tools directly, the model writes code that calls tools. The code executes in a sandboxed environment, and only the final result returns to the model."
- url: https://modelcontextprotocol.io/docs/2026-07-28/develop/clients/client-best-practices.md
- source_type: primary
- published: 2026-07-28
- confidence: high

### [12] 官方 MCP Registry（预览阶段）为公开 server 的集中元数据仓库，采用 server.json 标准格式与 DNS/GitHub 反向域名命名空间验证（如 io.github.user/server-name），由 Anthropic、GitHub、PulseMCP、Microsoft 等背书；生态覆盖 Claude、ChatGPT、VS Code、Cursor 等客户端
- quote: "The MCP Registry is the official centralized metadata repository for publicly accessible MCP servers, backed by major trusted contributors to the MCP ecosystem such as Anthropic, GitHub, PulseMCP, and Microsoft. ... Server names follow a reverse DNS format (like `io.github.username/server` or `com.example/server`) that ties them to verified GitHub accounts or domains."
- url: https://modelcontextprotocol.io/registry/about.md
- source_type: primary
- published: unknown
- confidence: high

### [13] MCP 设计原则明确：收敛优于选择（单一路径）、可组合优于特化（不为可用三原语拼出的功能加协议特性）、稳定优于速度（移除几乎不可能，按十年尺度设计）、标准优于创新（把已验证模式写入规范，扩展作为试验田）
- quote: "There should be one way to solve a problem in MCP. ... MCP provides foundational primitives: resources, tools, and prompts. We don't add protocol features for use cases that can be constructed from these existing building blocks. ... Adding to a protocol as widely adopted as MCP is easy. Removing from it is nearly impossible. ... We optimize for decades, not quarters."
- url: https://modelcontextprotocol.io/community/design-principles.md
- source_type: primary
- published: unknown
- confidence: high
