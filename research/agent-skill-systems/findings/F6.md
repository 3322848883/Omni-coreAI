# F6: AI agent tool/skill 系统可靠性与安全工程模式（沙箱、权限、版本、故障隔离、幂等、evals、审计）

## Findings

### [1] MCP 规范要求 tool 调用必须有 human-in-the-loop：客户端应展示暴露给模型的工具、在调用时给出视觉指示、对操作弹出确认以允许用户否决
- quote: "For trust & safety and security, there SHOULD always be a human in the loop with the ability to deny tool invocations."
- url: https://modelcontextprotocol.io/specification/2025-06-18/server/tools
- source_type: primary
- published: 2025-06-18
- confidence: high

### [2] MCP 明确规定 tool annotations（如只读/破坏性标记）在未受信任 server 上不可信，客户端 MUST 视为 untrusted
- quote: "For trust & safety and security, clients MUST consider tool annotations to be untrusted unless they come from trusted servers."
- url: https://modelcontextprotocol.io/specification/2025-06-18/server/tools
- source_type: primary
- published: 2025-06-18
- confidence: high

### [3] MCP tools 安全清单把「超时、审计日志、入参/出参校验、限流、敏感操作确认」写成 server MUST / client SHOULD 的规范义务，而非可选最佳实践
- quote: "Servers MUST: Validate all tool inputs, Implement proper access controls, Rate limit tool invocations, Sanitize tool outputs. Clients SHOULD: Prompt for user confirmation on sensitive operations... Implement timeouts for tool calls, Log tool usage for audit purposes"
- url: https://modelcontextprotocol.io/specification/2025-06-18/server/tools
- source_type: primary
- published: 2025-06-18
- confidence: high

### [4] Claude Code 沙箱用 OS 级强制隔离（macOS Seatbelt；Linux/WSL2 bubblewrap+socat）约束 Bash 子进程的文件系统与网络边界，而不是靠模型自觉
- quote: "Instead of approving each command, you define which files and network domains commands can touch, and the operating system enforces that boundary for every Bash, PowerShell, or Monitor command and its child processes."
- url: https://code.claude.com/docs/en/sandboxing
- source_type: primary
- published: unknown
- confidence: high

### [5] Claude Code 提供 failIfUnavailable + allowUnsandboxedCommands:false 作为托管部署的硬安全门：缺依赖则拒启动、禁止 dangerouslyDisableSandbox 逃逸重试
- quote: "a missing dependency such as bubblewrap on Linux blocks Claude Code from starting rather than showing a warning and falling back to unsandboxed execution; allowUnsandboxedCommands: false: Claude Code ignores the dangerouslyDisableSandbox escape hatch"
- url: https://code.claude.com/docs/en/sandboxing
- source_type: primary
- published: unknown
- confidence: high

### [6] Claude Code 凭据保护分 deny 与 mask 两档：deny 直接读屏蔽/剥环境变量；mask 给沙箱看哨兵值，仅在 allowlist 主机上由代理替换真值并可重签 AWS SigV4；项目级 settings 不得关闭文件系统隔离或注入凭据
- quote: "With mask, the sandboxed command sees a per-session sentinel value instead of the real one... When a request leaves the sandbox for one of them, the sandbox proxy replaces the sentinel with the real value."
- url: https://code.claude.com/docs/en/sandboxing
- source_type: primary
- published: unknown
- confidence: high

### [7] Claude Code 明确承认沙箱不是完整隔离边界：默认不检查 TLS 内容，允许 github.com 等宽域名存在 domain fronting 数据外泄路径，更强保证需自定义 TLS 终止代理
- quote: "code running inside the sandbox can potentially use domain fronting or similar techniques to reach hosts outside the allowlist. If your threat model requires stronger guarantees, configure a custom proxy that terminates TLS and inspects traffic"
- url: https://code.claude.com/docs/en/sandboxing
- source_type: primary
- published: unknown
- confidence: high

### [8] MCP Skills 扩展（SEP-2640 Final）要求 skill 文件清单含 SHA-256 digest + 字节数，宿主使用前 MUST 校验；持久化批准绑定完整 URI+digest 集合，任一文件增删改即撤销批准并须重新授权
- quote: "Verify each file's raw byte size and SHA-256 digest before use... Persisted approval MUST bind to the complete set of file URIs and digests. A changed, added, or removed file revokes that approval; the host MUST obtain approval again before loading or executing."
- url: https://modelcontextprotocol.io/extensions/skills/overview
- source_type: primary
- published: unknown (SEP-2640 Final)
- confidence: high

### [9] MCP Skills 把 skill 内容视为不可信输入：宿主侧代码执行与 allowed-tools 类权限授予需逐 skill 显式用户批准；同名 skill 不得静默覆盖；嵌套 skill 激活前须重新取得同意
- quote: "Treat skill content as untrusted input. Host-side code execution and permission grants such as allowed-tools require explicit per-skill user approval. Prevent skills with the same name from silently replacing one another."
- url: https://modelcontextprotocol.io/extensions/skills/overview
- source_type: primary
- published: unknown (SEP-2640 Final)
- confidence: high

### [10] MCP Skills 规定 skill 资源上限建议 512 文件 / 16 MiB，并要求宿主在连接/列目录/批准时禁止预取文件、批准只绑定清单不拉取内容——用完整性元数据换最少加载面
- quote: "Servers SHOULD NOT exceed 512 files or 16 MiB per skill... Hosts MUST NOT retrieve files ahead of need, including on connection, listing, or approval. Approval binds to the manifest without requiring file retrieval."
- url: https://modelcontextprotocol.io/extensions/skills/overview
- source_type: primary
- published: unknown (SEP-2640 Final)
- confidence: high

### [11] MCP 版本锁定策略：协议版本为 YYYY-MM-DD（最后一次破坏性变更日期），向后兼容变更不升版本；初始化时协商单一版本；废弃特性至少保留 12 个月（加急移除例外 90 天）
- quote: "The Model Context Protocol uses string-based version identifiers following the format YYYY-MM-DD... Deprecated features... remain in the specification for at least twelve months, or at least ninety days under the policy's expedited-removal exception"
- url: https://modelcontextprotocol.io/docs/2025-06-18/learn/versioning
- source_type: primary
- published: 2025-06-18
- confidence: high

### [12] MCP Security Best Practices 把本地 MCP server 一键安装/启动命令执行列为高危：客户端 MUST 在执行前展示完整未截断命令并取得显式同意，SHOULD 用容器/chroot/应用沙箱以最小默认权限运行
- quote: "Display a clear consent dialog before connecting a new local MCP server... Show the exact command that will be executed, without truncation... Execute MCP server commands in a sandboxed environment with minimal default privileges"
- url: https://modelcontextprotocol.io/specification/2025-06-18/basic/security_best_practices
- source_type: primary
- published: 2025-06-18
- confidence: high

### [13] MCP Security Best Practices 禁止 token passthrough：审计链断裂是核心风险之一（无法区分 MCP client 身份、下游日志来源失真），并要求 session ID 不得用于认证、必须绑定 user_id
- quote: "Token passthrough is explicitly forbidden... The MCP Server will be unable to identify or distinguish between MCP Clients... MCP Servers MUST NOT use sessions for authentication... combine the session ID with information unique to the authorized user, such as their internal user ID."
- url: https://modelcontextprotocol.io/specification/2025-06-18/basic/security_best_practices
- source_type: primary
- published: 2025-06-18
- confidence: high

### [14] MCP Security Best Practices 要求渐进最小权限 scope：初始只给低风险发现/读，高危操作首次触发时再 WWW-Authenticate 升权，并记录升权事件（请求 scope、授予子集、correlation ID）；反对通配符/全量 scope
- quote: "Minimal initial scope set... Incremental elevation via targeted WWW-Authenticate scope=\"...\" challenges... Log elevation events (scope requested, granted subset) with correlation IDs... Publishing all possible scopes in scopes_supported"
- url: https://modelcontextprotocol.io/specification/2025-06-18/basic/security_best_practices
- source_type: primary
- published: 2025-06-18
- confidence: high

### [15] Anthropic 工程实践：agent 自主性会放大错误，生产前应在沙箱环境做大量测试并加护栏；任务终止需显式停止条件（如最大迭代次数）；工具接口设计（ACI）应与 HCI 同等投入
- quote: "The autonomous nature of agents means higher costs, and the potential for compounding errors. We recommend extensive testing in sandboxed environments, along with the appropriate guardrails... it's also common to include stopping conditions (such as a maximum number of iterations) to maintain control."
- url: https://www.anthropic.com/engineering/building-effective-agents
- source_type: primary
- published: 2024-12-19
- confidence: high

### [16] MCP SEP-2484（2026-03-27 创建，Final）把 conformance test 作为 Standards Track SEP 进入 Final 的门槛：每个 MUST/MUST NOT/SHOULD 必须映射到可执行 check 或文档化 exclusion，且 tier 评估对「钉死的 conformance 版本」跑，避免新检查造成意外回归
- quote: "a conformance scenario covering its normative requirements must be merged into the conformance repository, accompanied by a structured traceability file mapping each MUST/MUST NOT and SHOULD/SHOULD NOT to a check or a documented exclusion... tier assessments are run against a pinned conformance release version"
- url: https://modelcontextprotocol.io/seps/2484-conformance-tests-required-for-final-seps.md
- source_type: primary
- published: 2026-03-27
- confidence: high

### [17] MCP Inspector CLI 提供可脚本化的 CI 回归基元：单次 request 后退出、稳定退出码 0–5（区分 auth_required / unreachable / tool isError）、stderr 单行 JSON error envelope、`--stored-auth-only` 避免 CI 卡在交互 OAuth
- quote: "Every non-zero exit maps to a stable failure class... a single JSON line to stderr... --stored-auth-only: never start interactive OAuth... This is the flag CI wants."
- url: https://modelcontextprotocol.io/docs/2026-07-28/tools/inspector/cli
- source_type: primary
- published: 2026-07-28
- confidence: high
