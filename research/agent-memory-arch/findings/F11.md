# F11: 多 agent 讨论/辩论模式

## Findings

### [1] TradingGPT 的 inter-agent debate 触发条件是「同一股票出现在多个 agent 组合中」，流程是共享 top-K 分层记忆 + immediate reflection（含推荐/交易量/收益），同伴反馈写入 debate 记忆类；论文未给出轮次上限或共识终止条件。
- quote: "For stocks that appear in multiple agents' trading portfolios, TradingGPT enables inter-agent dialogue via a debate mechanism. ... agents present their top-K layered memories as well as immediate reflections, encompassing recommendations, trade values, volumes, and returns, inviting feedback from their peers. All feedback is subsequently stored in the debate class of the Agents' Cognition Schema"
- url: https://arxiv.org/html/2309.03736v1
- source_type: primary
- published: 2023-09-07
- confidence: high

### [2] TradingGPT 是「先单 agent 出信号、再多 agent 辩论」两阶段；测试阶段把个人记忆与辩论交换同时喂给 LLM 做交易决策，辩论发生在训练工作流而非无限讨论环。
- quote: "the agent collaborates in the multi-agent phase, joining debates with agents trading the same stock from varied sectors on that day ... Both individually processed memories and insights from inter-agent exchanges are concurrently inputted into the LLM to inform trading decisions."
- url: https://arxiv.org/html/2309.03736v1
- source_type: primary
- published: 2023-09-07
- confidence: high

### [3] TradingGPT 论文自述仍处 prompt 设计与 ablation 前期（GPT-3.5-turbo backbone），即其 debate 机制细节（轮数/终止）缺乏实验验证，不能当作已定型的生产协议。
- quote: "Our research consists of two phases: prompt design and ablation studies. We've crafted efficient LLM prompts using GPT3.5 turbo as the backbone. ... we're poised to undertake ablation studies"
- url: https://arxiv.org/html/2309.03736v1
- source_type: primary
- published: 2023-09-07
- confidence: high

### [4] Du et al. 2023 multiagent debate 的主实验配置是 3 agents × 2 rounds；性能随轮次上升但 4 轮以上趋于平台，因此经验上 2–4 轮是收敛/成本折中区。
- quote: "we evaluate our approach across benchmarks mainly using three agents with two rounds of debates ... we found that additional debate rounds above four led to a similar final performance to 4 rounds of debate."
- url: https://arxiv.org/html/2305.14325v1
- source_type: primary
- published: 2023-05-23
- confidence: high

### [5] Du et al. 的终止不是硬共识阈值，而是固定轮次后取更新后的答案；收敛靠 prompt 控制「固执度」——鼓励坚持己见的 long prompt 辩论更久、终解更好，short prompt 更快达成一致；作者发现 LLM 天生偏 "agreeable"。
- quote: "We found that we could control the duration of debates by how changing how much a language model trusts its own outputs over those generated by other models through different prompts. ... prompts that encouraged models to be more "stubborn' based on their own solutions led to longer debates and better final solutions. Overall, we observed that language model agents were relatively "agreeable""
- url: https://arxiv.org/html/2305.14325v1
- source_type: primary
- published: 2023-05-23
- confidence: high

### [6] FinCon 不用开放式 peer-to-peer 辩论：采用 manager-analyst 层级（7 类分析师单模态蒸馏 + manager 唯一决策），双层风控（episode 内 CVaR 触发风险规避，跨 episode Conceptual Verbal Reinforcement 更新投资信念），并选择性回传信念以降低通信成本。
- quote: "a dual-level risk-control component enhances decision-making by monitoring daily market risk and updating systematic investment beliefs through self-critique. These conceptualized beliefs provide verbal reinforcement for future decisions, selectively propagated to relevant agents, improving performance while reducing unnecessary peer-to-peer communication costs."
- url: https://arxiv.org/html/2407.06567v3
- source_type: primary
- published: 2024-07-09 (v3 2024-11-07)
- confidence: high

### [7] FinCon 的 verbal reinforcement 用 textual gradient descent 更新 prompt：优化方向由「更盈利 vs 更差 episode 的概念化洞察对比」给出，学习率 τ = 相邻两个 episode 交易决策序列的重叠百分比；CVRF 训练期专用，within-episode CVaR 风控在训练与测试都生效。
- quote: "we derive investment belief updates by measuring the overlapping percentage of trading actions between two consecutive training trajectories at each belief update ... The over-episode mechanism functions exclusively during the training stage ... CVRF leverages text-based gradient descent to offer optimal conceptual investment guidance for the manager agent"
- url: https://arxiv.org/html/2407.06567v3
- source_type: primary
- published: 2024-07-09 (v3 2024-11-07)
- confidence: high

### [8] Anthropic Research 多 agent 是 orchestrator-worker 而非辩论：lead agent 规划并 spawn 并行 subagent，子 agent 返回摘要后由 lead 决定是否继续研究；同步执行，token 成本约为 chat 的 15×，多 agent（Opus 4 lead + Sonnet 4 sub）在内部 research eval 比单 Opus 4 高 90.2%。
- quote: "Our Research system uses a multi-agent architecture with an orchestrator-worker pattern ... The LeadResearcher synthesizes these results and decides whether more research is needed—if so, it can create additional subagents or refine its strategy. Once sufficient information is gathered, the system exits the research loop ... multi-agent systems use about 15× more tokens than chats."
- url: https://www.anthropic.com/engineering/built-multi-agent-research-system
- source_type: primary
- published: 2025-06-13
- confidence: high

### [9] Anthropic 用「查询复杂度 → 预算」规则防过度讨论：简单事实查找 1 agent / 3–10 次工具调用，直接对比 2–4 subagent / 各 10–15 次调用，复杂研究 >10 subagent；早期失败模式包括给简单查询 spawn 50 个 subagent、无尽搜索，靠 prompt 内嵌 effort scaling + guardrails 约束。
- quote: "Simple fact-finding requires just 1 agent with 3-10 tool calls, direct comparisons might need 2-4 subagents with 10-15 calls each, and complex research might use more than 10 subagents ... Early agents made errors like spawning 50 subagents for simple queries, scouring the web endlessly for nonexistent sources"
- url: https://www.anthropic.com/engineering/built-multi-agent-research-system
- source_type: primary
- published: 2025-06-13
- confidence: high

### [10] Claude Code sub-agent 是隔离上下文的委派（非讨论）：独立 context window / system prompt / 工具与权限，用 `maxTurns` 限制 agentic 轮次，触顶后返回 partial 输出可 resume；内置 Explore/Plan 为只读研究 agent，避免污染主对话。
- quote: "Each subagent runs in its own context window with a custom system prompt, specific tool access, and independent permissions. ... maxTurns: Maximum number of agentic turns before the subagent stops. When the subagent reaches the limit, Claude Code returns its output marked as partial, and Claude can resume it to continue."
- url: https://code.claude.com/docs/en/sub-agents
- source_type: primary
- published: unknown (docs current 2026)
- confidence: high

### [11] AutoGen AgentChat 把「何时停」抽象为可组合的 TerminationCondition（AND/OR 组合），内建 11 种：MaxMessage / TextMention(如 "TERMINATE"/"APPROVE") / TokenUsage / Timeout / Handoff / SourceMatch / External / StopMessage / TextMessage / FunctionCall / Functional；典型 critic-primary 用 "APPROVE" 文本或 `approve` 工具调用终止。
- quote: "a run can go on forever, and in many cases, we need to know when to stop them. This is the role of the termination condition. ... They can be combined using the AND and OR operators. ... MaxMessageTermination: Stops after a specified number of messages ... TextMentionTermination: Stops when specific text or string is mentioned in a message (e.g., "TERMINATE"). ... TimeoutTermination: Stops after a specified duration in seconds."
- url: https://microsoft.github.io/autogen/stable/user-guide/agentchat-user-guide/tutorial/termination.html
- source_type: primary
- published: unknown (AutoGen 0.4 docs)
- confidence: high

### [12] CrewAI 协作靠 `allow_delegation=True` 注入 Delegate work / Ask question 两个工具；无限讨论的已知故障是「Too Much Back-and-Forth」和「Delegation Loops」，官方修复是层级分工（manager 可委派、specialist 设 allow_delegation=False 禁止再委派）而非共识阈值。
- quote: "Issue: Too Much Back-and-Forth ... Agents ask excessive questions, slow progress. ... Issue: Delegation Loops ... Agents delegate back and forth indefinitely. ✅ Solution: Clear hierarchy and responsibilities ... specialist1 = Agent(role="Specialist A", allow_delegation=False)  # No re-delegation"
- url: https://docs.crewai.com/en/concepts/collaboration
- source_type: primary
- published: unknown (docs current 2026)
- confidence: high

### [13] LangGraph 用全局步数 `recursion_limit` 作为多 agent/循环图的硬性防死循环开关：超限抛 GRAPH_RECURSION_LIMIT，可在 invoke config 里调高（如 1000）；框架本身不内置「共识阈值」终止，终止逻辑由图结构/节点条件显式建模。
- quote: "Your LangGraph StateGraph reached the maximum number of steps before hitting a stop condition. This is often due to an infinite loop ... you can pass in a higher recursion_limit value into your config object when invoking your graph like this: graph.invoke({...}, {"recursion_limit": 1000})"
- url: https://docs.langchain.com/oss/python/langgraph/errors/GRAPH_RECURSION_LIMIT.md
- source_type: primary
- published: unknown (docs current 2026)
- confidence: high

### [14] MAD 基准（Smit et al., InstaDeep）显示多 agent 辩论并不稳定优于 self-consistency / Medprompt，但对超参极敏感；Multi-Persona 的 judge agent 可在满意时提前结束辩论，prompt 级「agreement intensity」（"you should agree with the other agents X% of the time"）在 USMLE 上给 Multi-Persona ≈+15%、SoM ≈+5% 准确率。
- quote: "The judge has additional agency to end the debate early if it is satisfied with the answers provided. ... Our prompt takes the following simple form: "you should agree with the other agents X% of the time". ... modulating the agreement intensity in this way provides a substantial (≈15%) improvement in performance for Multi-Persona, and (≈5%) for SoM on the USMLE dataset."
- url: https://arxiv.org/html/2311.17371v3
- source_type: primary
- published: 2023-11-29 (v3 2024-07-18)
- confidence: high

### [15] 跨系统防无限讨论的共同模式：硬上限（轮次/消息数/token/时间/步数）+ 软共识触发（APPROVE 文本、approve 工具、judge 满意）+ 组织结构限流（层级单点决策、禁止 specialist 再委派、effort 预算）；纯「共识阈值比例投票」在上述工程文档中较少作为唯一终止条件。
- quote: "combined_termination = max_msg_termination | text_termination ... We'll create a team that stops either after 10 messages are generated or when the critic agent approves a message."
- url: https://microsoft.github.io/autogen/stable/user-guide/agentchat-user-guide/tutorial/termination.html
- source_type: primary
- published: unknown (AutoGen 0.4 docs)
- confidence: medium
