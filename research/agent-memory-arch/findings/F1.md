# F1: 厂商记忆架构

## Findings

### [1] OpenAI ChatGPT memory is dual-channel: explicit "saved memories" plus inferred "chat history" insights from past chats (rolled out 2025-04-10), with free users later getting only lightweight short-term continuity (2025-06-03).
- quote: "Memory in ChatGPT is now more comprehensive. In addition to the saved memories that were there before, it now references all your past conversations... memory now works in two ways: 'saved memories' you've asked it to remember and 'chat history', which are insights ChatGPT gathers from past chats to improve future ones."
- url: https://openai.com/index/memory-and-new-controls-for-chatgpt/
- source_type: primary
- published: 2024-02-13 (updated 2025-04-10 / 2025-06-03)
- confidence: high

### [2] OpenAI "Dreaming" is a background memory-synthesis pipeline that curates memory by referencing chat history without requiring explicit "remember this" cues; Dreaming V3 is the 2026 scalable architecture now rolling out to Plus/Pro.
- quote: "dreaming leverages a background process that allows ChatGPT to learn from many conversations and synthesize ChatGPT's memory state in order to always provide the freshest, most relevant context to your conversations. Dreaming also makes it easier for memory to include context that occurs naturally in conversation, without relying on explicit requests to remember something."
- url: https://openai.com/index/chatgpt-memory-dreaming/
- source_type: primary
- published: 2026-06-04
- confidence: high

### [3] OpenAI Dreaming explicitly targets staleness, correctness, and multi-year scalability; evals compare 2024 saved-memories vs 2025 Dreaming V0 vs 2026 Dreaming V3 on carry-forward, preference-following, and time-awareness.
- quote: "Today we're beginning to roll out a more capable and scalable system for synthesizing memory, developed to tackle the staleness, correctness, and scalability challenges that we observe when memory is applied to the hundreds of millions of users and multi-year time horizons in ChatGPT."
- url: https://openai.com/index/chatgpt-memory-dreaming/
- source_type: primary
- published: 2026-06-04
- confidence: high

### [4] OpenAI cut Dreaming serving compute ~5x to make free-tier memory practical, and uses a "memory summary page" as the human-reviewable projection of synthesized memory state.
- quote: "Recent improvements reduced the compute required to serve dreaming to Free users by approximately 5x, making it possible to begin rolling out dreaming to Free users over the coming weeks and to increase memory capacity for Plus and Pro users."
- url: https://openai.com/index/chatgpt-memory-dreaming/
- source_type: primary
- published: 2026-06-04
- confidence: high

### [5] OpenAI memory objects are decoupled from conversation threads: deleting a chat does not erase memories derived from it; users must delete the memory entry itself (Settings > Personalization > Manage Memory).
- quote: "ChatGPT's memories evolve with your interactions and aren't linked to specific conversations. Deleting a chat doesn't erase its memories; you must delete the memory itself."
- url: https://openai.com/index/memory-and-new-controls-for-chatgpt/
- source_type: primary
- published: 2024-02-13
- confidence: high

### [6] Anthropic's platform memory tool is client-side and file-based: Claude requests CRUD ops under a `/memories` prefix; the application owns storage (files, DB keys) and returns tool_results — Anthropic does not host the memory store.
- quote: "The memory tool operates client-side: Claude requests file operations, and your application executes them. You control where and how the data is stored through your own infrastructure."
- url: https://platform.claude.com/docs/en/agents-and-tools/tool-use/memory-tool
- source_type: primary
- published: unknown (docs; paired with 2025-09-29 announcement)
- confidence: high

### [7] Anthropic memory uses just-in-time retrieval (not bulk preload): the agent checks the memory directory at task start and reads files on demand, keeping the active context window small for long-running sessions.
- quote: "Memory supports just-in-time context retrieval. Rather than loading all relevant information up front, an agent records what it learns in memory files and reads them back on demand. This keeps the active context focused on the current task, which matters for long-running sessions that would otherwise overwhelm the context window."
- url: https://platform.claude.com/docs/en/agents-and-tools/tool-use/memory-tool
- source_type: primary
- published: unknown (docs)
- confidence: high

### [8] Anthropic memory tool command surface is a file protocol: `view` (with optional `view_range`), `create` (create-or-overwrite), `str_replace`, `insert` (by `insert_line`), `delete` — all must be path-traversal-restricted to `/memories`; file views truncate at 16,000 chars.
- quote: "Your client-side implementation must handle the following commands... view / create / str_replace / insert / delete... Your implementation must validate every path in every command to prevent directory traversal attacks."
- url: https://platform.claude.com/docs/en/agents-and-tools/tool-use/memory-tool
- source_type: primary
- published: unknown (docs)
- confidence: high

### [9] Anthropic pairs memory with context editing (client-side eviction of stale tool results) and compaction (server-side summarization); on internal agentic-search evals, memory+context-editing improved performance 39% over baseline, context-editing alone 29%, and a 100-turn web-search eval cut token use 84%.
- quote: "combining the memory tool with context editing improved performance by 39% over baseline. Context editing alone delivered a 29% improvement. In a 100-turn web search evaluation, context editing enabled agents to complete workflows that would otherwise fail due to context exhaustion—while reducing token consumption by 84%."
- url: https://claude.com/blog/context-management
- source_type: primary
- published: 2025-09-29
- confidence: high

### [10] Microsoft 365 Copilot stores memories (saved memories + chat-history-inferred details + custom instructions) in a hidden folder in the user's Exchange mailbox (eDiscovery item class `IPM.Contact`, folder `CopilotMemory`), inheriting mailbox security/compliance controls.
- quote: "Memories, which include saved memories, details inferred from chat history and custom instructions, are stored in the user's Exchange mailbox in a hidden folder. Thus, memories follow the same security and compliance policies as other mailbox data, such as Customer Lockbox and encryption at rest."
- url: https://learn.microsoft.com/en-us/microsoft-365/copilot/copilot-personalization-memory
- source_type: primary
- published: 2026-09-02 (last updated)
- confidence: high

### [11] Microsoft Copilot memory has three layers with different lifecycles: saved memories persist until user delete; chat-history details are dynamic and may be discarded as Copilot "learns what's most helpful"; Purview retention labels do not apply to Copilot memory (no admin retention controls for it).
- quote: "Saved memories are retained until the end-user explicitly deletes the saved memory... Details from the chat history are dynamic. Copilot might update or discard older details as it learns what's most helpful to retain... Retention policies and retention labels configured in Purview by organization admins don't apply to Copilot memory."
- url: https://learn.microsoft.com/en-us/microsoft-365/copilot/copilot-personalization-memory
- source_type: primary
- published: 2026-09-02
- confidence: high

### [12] Copilot Studio agent memory (preview) uses a Capture→Store→Apply lifecycle with per-user folders in Microsoft-managed storage; 28-day inactivity TTL deletes user memory; memory is off in group chats/Teams channels; users manage via chat or a memory portal.
- quote: "Each user's memory lives in a dedicated folder in Microsoft-managed storage that the agent reads from and writes to. The lifecycle is always the same: Capture: The agent records signals such as user preferences and relevant context... Store: These signals are saved as files in that folder. Apply: On subsequent interactions, the agent reads from this memory to inform its responses or decisions."
- url: https://learn.microsoft.com/en-us/microsoft-copilot-studio/agents-experience/memory-overview
- source_type: primary
- published: 2026-08-03 (last updated)
- confidence: high

### [13] Gemini Enterprise builds a personal Memory from three intake channels — explicit saved memories, a structured personalization profile (name/role/industry), and insights extracted from connected work sources (email/calendar/docs) plus conversation history — with admin ability to disable Memory/personalization (default on).
- quote: "As you use Gemini Enterprise, it builds a personal Memory by understanding your individual needs and work patterns... When you connect your work applications, such as Microsoft Outlook and Microsoft OneDrive, Gemini Enterprise can extract insights from your email, calendar, and documents to provide deep contextual assistance."
- url: https://docs.cloud.google.com/gemini/enterprise/docs/configure-personalization
- source_type: primary
- published: unknown (docs)
- confidence: high

### [14] Cross-vendor injection pattern: none of the four vendors auto-dumps raw chat logs into every prompt — they synthesize or select compact memory artifacts (OpenAI dreaming state / MS Graph-grounded prompt / Gemini Memory+profile / Anthropic on-demand file reads) and inject only the curated slice, with user-visible manage/delete surfaces.
- quote: "Copilot preprocesses the input prompt by using grounding and accesses Microsoft Graph in the user's tenant... Grounding improves the specificity of your prompt, and helps you get answers that are relevant and actionable to your specific task."
- url: https://learn.microsoft.com/en-us/microsoft-365/copilot/microsoft-365-copilot-architecture
- source_type: primary
- published: 2026-09-14
- confidence: medium
