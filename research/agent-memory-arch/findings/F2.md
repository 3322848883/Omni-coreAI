# F2: 开源 agent memory 框架

## Findings

### [1] MemGPT 用 OS 式虚拟上下文管理：LLM context 作 fast tier，外部存储作 slow tier，靠 function calls / interrupts 在两层间搬数据，而不是把全部历史塞进 prompt。
- quote: "we propose virtual context management, a technique drawing inspiration from hierarchical memory systems in traditional operating systems that provide the appearance of large memory resources through data movement between fast and slow memory."
- url: https://arxiv.org/abs/2310.08560
- source_type: primary
- published: 2023-10-12 (v2 2024-02-12)
- confidence: high

### [2] Letta 是 MemGPT 的现行产品化形态（f.k.a. MemGPT）；2025–2026 主线已迁到 letta-code，旧 Python API server 仅留在 archive 分支，选型时要注意活跃实现不是原论文仓库主线。
- quote: "Letta (f.k.a. MemGPT) is actively developed. The current source code lives in [`letta-ai/letta-code`] ... The [`archive`] branch contains the retired Letta V1 API server."
- url: https://github.com/letta-ai/letta
- source_type: primary
- published: unknown (readme current as of fetch 2026-09-28)
- confidence: high

### [3] LangGraph 把记忆拆成 thread 级 short-term（graph State + checkpointer 落库）与跨会话 long-term（BaseStore + 自定义 namespace），持久化策略与检索入口是两条独立路径。
- quote: "LangGraph manages short-term memory as a part of your agent's state. State is persisted to a database using a checkpointer so the thread can be resumed at any time. ... Long-term memory stores user-specific or application-level data across sessions ... LangGraph provides stores to let you save and recall long-term memories."
- url: https://docs.langchain.com/oss/python/langgraph/memory
- source_type: primary
- published: unknown (docs current as of fetch 2026-09-28)
- confidence: high

### [4] LangGraph 官方把长期记忆按 CoALA 映射为 semantic（事实）/ episodic（经历）/ procedural（规则=system prompt），并明确 semantic 有两种组装方式：持续更新的 Profile（JSON 键值）vs 文档 Collection；Profile 易随体积变大出错，Collection 召回更高但更新更难，Store 检索侧支持 semantic search + content filter。
- quote: "A profile is generally just a JSON document with various key-value pairs you've selected to represent your domain. ... a document collection tends to lead to higher recall downstream. However, this shifts some complexity memory updating. ... The Store currently supports both semantic search and filtering by content."
- url: https://docs.langchain.com/oss/python/langgraph/memory
- source_type: primary
- published: unknown (docs current as of fetch 2026-09-28)
- confidence: high

### [5] Graphiti（Zep 开源核心）是 temporal knowledge graph，而非向量库：存储 Entities/Facts（带 validity window，旧事实 invalidate 不 delete）/Episodes（provenance）/自定义 Pydantic ontology；支持增量写入，不做全图重算。
- quote: "Temporal Fact Management: Facts have validity windows. When information changes, old facts are invalidated — not deleted. ... Incremental Graph Construction: New data integrates immediately without batch recomputation."
- url: https://github.com/getzep/graphiti
- source_type: primary
- published: unknown (readme current as of fetch 2026-09-28; paper arXiv:2501.13956)
- confidence: high

### [6] Graphiti 检索层是 hybrid：semantic embedding + BM25 keyword + graph traversal 三路融合，且明确不依赖 LLM summarization 做检索；对比 GraphRAG 自称检索延迟 sub-second vs 秒到数十秒。
- quote: "Hybrid Retrieval: Combines semantic embeddings, keyword (BM25), and graph traversal for low-latency, high-precision queries without reliance on LLM summarization."
- url: https://github.com/getzep/graphiti
- source_type: primary
- published: unknown (readme current as of fetch 2026-09-28)
- confidence: high

### [7] Graphiti 开源自托管需自备图库：要求 Neo4j 5.26 / FalkorDB 1.1.2 / Neptune(+OpenSearch Serverless)；Kuzu 0.11.2 已 deprecated。托管版 Zep 用私有 Context Graph Engine，宣称 sub-200ms 检索，两者持久化栈不同。
- quote: "Neo4j 5.26 / FalkorDB 1.1.2 / Amazon Neptune ... Kuzu 0.11.2 (deprecated) ... Zep is powered by a proprietary graph database — the Context Graph Engine — built for millions of context graphs with low-latency retrieval"
- url: https://github.com/getzep/graphiti
- source_type: primary
- published: unknown (readme current as of fetch 2026-09-28)
- confidence: high

### [8] Zep/Graphiti 论文（arXiv:2501.13956, 2025-01）声称在 MemGPT 团队自建的 DMR 上 94.8% vs MemGPT 93.4%，LongMemEval 上准确率最高 +18.5% 且响应延迟降 90%——对比基线是 MemGPT，不是 LangGraph/Mem0。
- quote: "Zep demonstrates superior performance (94.8% vs 93.4%) ... accuracy improvements of up to 18.5% while simultaneously reducing response latency by 90% compared to baseline implementations."
- url: https://arxiv.org/abs/2501.13956
- source_type: primary
- published: 2025-01 (arXiv:2501.13956)
- confidence: high

### [9] Mem0 论文（arXiv:2504.19413）架构是 extract → consolidate → retrieve 的记忆抽取管线，并另有 graph memory 变体；LOCOMO 上比 full-context 省 >90% token、p95 延迟低 91%，graph 版总分约比基础版高 2%。
- quote: "Mem0, a scalable memory-centric architecture that addresses this issue by dynamically extracting, consolidating, and retrieving salient information ... Mem0 with graph memory achieves around 2% higher overall score than the base configuration ... 91% lower p95 latency and saves more than 90% token cost"
- url: https://arxiv.org/abs/2504.19413
- source_type: primary
- published: 2025 (arXiv:2504.19413)
- confidence: high

### [10] Mem0 2026-04 新算法改为 single-pass ADD-only 抽取（一次 LLM 调用，无 UPDATE/DELETE，记忆只累积不覆盖），检索改 multi-signal（semantic + BM25 + entity matching 并行分融合）并带 temporal reasoning；托管平台 LoCoMo 92.5 / LongMemEval 94.4，官方注明 OSS SDK 数字不会完全一致。
- quote: "Single-pass ADD-only extraction -- one LLM call, no UPDATE/DELETE. Memories accumulate; nothing is overwritten. ... Multi-signal retrieval -- semantic, BM25 keyword, and entity matching scored in parallel and fused. ... open-source users should expect directionally similar gains but not identical numbers."
- url: https://github.com/mem0ai/mem0
- source_type: primary
- published: 2026-04 (readme "New Memory Algorithm (April 2026)")
- confidence: high

### [11] Memobase 走 user-profile 路线而非记忆条目检索：每用户常驻 profile + event timeline，读路径是少量 SQL、宣称 <100ms；写路径用 per-user buffer 批处理，v0.0.40 把单次跑批 LLM 调用固定为 3 次、token 成本约降 40–50%，且系统内刻意不做 agent 以控成本。
- quote: "for each user, there is always a user profile and event timeline available ... keeping online latency under 100ms. ... reducing the number of LLM calls in a single run from approximately 3-10 times to a fixed 3 times, which reduces token costs by approximately 40-50%."
- url: https://github.com/memodb-io/memobase
- source_type: primary
- published: 2026-01-11 (repo pushed_at); version notes in readme
- confidence: high

### [12] Cognee 定位是自托管 AI memory platform：文档/代码/对话 ingest 成知识图谱供 agent 复用；无 LLM key 时用本地 GLiNER + 本地 embedding（CPU），论文 arXiv:2505.24478 专攻 KG–LLM 接口优化，与 Mem0/Zep 的对话记忆抽取路线不同。
- quote: "Turn documents, code, and conversations into a self-hosted knowledge graph your agents can search and reuse. ... With no LLM key configured, Cognee extracts the graph with the local GLiNER model and embeds with a local embedding model"
- url: https://github.com/topoteretes/cognee
- source_type: primary
- published: 2025 (paper arXiv:2505.24478 Markovic et al.)
- confidence: high
