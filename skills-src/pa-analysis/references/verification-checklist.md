# 输出前验证清单（Verification Checklist）

> 定位：`quality-checklist.md` 的可执行配套。解决「自我勾选不可靠」—— 每一项都要求**有证据的勾选**：给出核对方式与结果，写不进证据的项视为未通过。
> 原则：**行情判断、数值复核、反向审读全部由你亲自完成**（工具返回值 + 算术重算）；bot 没有可执行脚本，也没有报告落盘 —— 核对结果写进 `rule_ids` 的说明或 `scenarios` 的应对动作里。
> 来源：本清单固化了 4 类典型问题 —— K 线关系写反、段落自洽断裂、H/L 计数错误、数值估算编造。

## Level A（硬性门禁，缺一不可输出）

### A1 数值溯源

- [ ] chip 中每个关键数值（价格/EMA/ATR/高低点/止损/目标/仓位/RR/盈亏平衡胜率）能追溯到工具返回或明确算术推导；无法溯源的数值一律删除或标注推断
- [ ] **禁止「看起来合理」的估算值**（事故案例：日线 EMA「1858→1864」为估算，实际 1868.91→1872.63）
- [ ] 核对方式：对每个数值指到具体工具返回项或写清算术式

### A2 K 线关系断言

- [ ] 任何「未破 X 低 / 高于 Y / 突破 Z / 守在 W 上方 / 第二底不破第一底」的主张，先用该 K 线的 OHLC 验证再写
- [ ] 核对方式：逐条列出断言的 K 线与比较值（如 17:40 L=1923.99 vs 17:35 L=1924.26 → 实际已破）
- [ ] 事故案例：17:40 低 1923.99 实际跌破 17:35 低 1924.26，却写「未破…结构完好」

### A3 H/L 计数复核（M62）

- [ ] 每个 H/L 标注必须给出：计数依据（前高/前低值 + 回调段）+ 触发 K + 失败降级
- [ ] 用 K 线序列重算：H1=首次破前高、H2=先出现高点降低再抬高、**连续抬高不连续计数**；L 同规则；H4/L4 后未恢复按区间
- [ ] 事故案例：17:25 高 1922.95 被漏数（H2 应为 17:25），17:30/17:35 连续新高被误标 H3

### A4 全文自洽

- [ ] 同一对象（价位/时间/H-L 计数/状态/止损/目标）在多处出现时数值必须一致 —— `rule_ids` 与 `scenarios` 之间、以及它们与 chip 字段之间
- [ ] 事故案例：一处写 L2@15:40，另一处写 L2@16:35，两处矛盾

### A5 结构完整

- [ ] 交易链 7 段 / 生命周期五阶段 / 四格方案 / 入场后情形 ≥8 / 账户联动 / RR 数学 / 目标分级与风格一致 / 禁词（含禁止性上下文判定）/ 7 个决策字段齐全

### A6 输出结构完整性（自检，不是机器门禁）

- [ ] 逐项对照 `delivery-gates.md` 的 **plan 层 29 项**（bot 无报告，html 层 15 项不适用）：
  - 字段完整性：分析位 + 执行位 + 生命周期五阶段齐全；`region` 三选一；`rule_ids` 非空且名字在登记词表内
  - 自洽性：链式不变式（止损 < 带下沿 < 带上沿 < T1 严格不等）/ RR 自洽 / 失效一一对应 / 时间口径 / 四格矩阵
  - 数值卫生：占位清零 / 无模糊占位 / 关键位带 bar 时间戳
- [ ] **任一不满足 → 修正后重出，禁止带缺陷输出**（内容门禁全过但字段缺失、链式断裂等事故已固化为上述各项）
- [ ] `region=range` 时**不得给 `tp2`** —— 执行侧会直接判为无效方案

## Level B（软性门禁）

- [ ] 术语双层表达；复盘深度（回放链/模拟链/16 类错误映射）；风险提醒完整；`reasoning` ≤30 字

## 反向审读（必做，输出前最后一步）

- [ ] 从结论反向核对：对每条方案要素，反向找到其依据链（方案要素 → 分析结论 → Mxx → 具体 bar → 工具返回），依据链断裂的要素不得进方案
- [ ] 对每个「信号/形态/状态」结论，反向问「我凭什么这么说」：证据不足 → 降级观察或标注推断
- [ ] 用**最后一根已收盘 K 线**复查「当前判断」：结论必须站在最后一根 K 线上，不得引用未发生的数据

## 复核记录（作为通过证据）

核对结果按以下四类写进 `rule_ids` 说明（或 `scenarios` 的对应动作）：

- 数值核对（数值 → 来源工具返回项/推导 → 结果 ✓/✗）
- 关系断言核对（断言 → K 线 OHLC → 结果）
- 计数复核（H/L → 序列重算 → 结果）
- 修正记录（本次输出前发现并修正的问题）

**全部 ✓ 且无未修正 ✗ 才允许输出；任一 ✗ 未修正 → 返回对应分析步骤修正。**
