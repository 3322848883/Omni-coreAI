# 交付前验证清单（Verification Checklist）

> 定位：`quality-checklist.md` 的可执行配套。解决"自我勾选不可靠"——每一项都要求**有证据的勾选**：给出核对方式与结果，写不进证据的项视为未通过。
> 原则：分析零脚本——行情判断、数值复核、反向审读全部由 AI 亲自完成（只读 DB 查询 + 全文检索 + 算术重算），不引入分析脚本；**唯一例外是 A6/现价对表两个交付门禁脚本**（validate_report.py / plan_pulse.py），它们不做任何分析判断，只机械验证交付物物理完整性与拉取实时价对照，属于"机器卡门禁"而非"机器做分析"。
> 来源：本清单固化了 4 类典型问题——K 线关系写反、段落自洽断裂、H/L 计数错误、数值估算编造。

## Level A（硬性门禁，缺一不可交付）

### A1 数值溯源
- [ ] 报告与 plan-json 中每个关键数值（价格/EMA/ATR/高低点/止损/目标/仓位/RR/盈亏平衡胜率）能追溯到 kline.db / account.db 或明确算术推导；无法溯源的数值一律删除或标注推断
- [ ] 禁止"看起来合理"的估算值（事故案例：日线 EMA"1858→1864"为估算，DB 实际 1868.91→1872.63）
- [ ] 核对方式：对报告每个数值执行 SELECT 查询或算术重算，结果写入报告"数据复核记录"

### A2 K 线关系断言
- [ ] 任何"未破 X 低 / 高于 Y / 突破 Z / 守在 W 上方 / 第二底不破第一底"的主张三段式验证：先用该 K 线的 OHLC 数据验证再写
- [ ] 核对方式：逐条列出断言的 K 线与比较值（如 17:40 L=1923.99 vs 17:35 L=1924.26 → 实际已破）
- [ ] 事故案例：17:40 低 1923.99 实际跌破 17:35 低 1924.26，报告误写"未破…结构完好"

### A3 H/L 计数复核（M62）
- [ ] 每个 H/L 标注必须给出：计数依据（前高/前低值 + 回调段）+ 触发 K + 失败降级
- [ ] 用 K 线序列重算：H1=首次破前高、H2=先出现高点降低再抬高、**连续抬高不连续计数**；L 同规则；H4/L4 后未恢复按区间
- [ ] 事故案例：17:25 高 1922.95 被漏数（H2 应为 17:25），17:30/17:35 连续新高被误标 H3

### A4 段落自洽
- [ ] 同一对象（价位/时间/H-L 计数/状态/止损/目标）在全报告多处出现时数值必须一致；用全文检索核对同一字符串的出现次数与上下文
- [ ] 事故案例：S1 写 L2@15:40，图A/7.3 写 L2@16:35，两处矛盾

### A5 结构完整（原 quality-checklist 一~五 并入本层）
- [ ] 7 层 / 4 方案 / 交易链 7 段 / lifecycle 五阶段 / plan-json schema / 映射表 / 账户联动 / RR 数学 / 目标分级与风格一致 / 禁词（含禁止性上下文判定）

### A6 物理完整性（机器门禁，validate_report.py 全绿）
- [ ] 运行 `scripts/validate_report.py <报告路径>`，29 项全部 PASS：
      1-8 物理完整性：占位符清零 / HTML 闭合 / plan-json 可解析 / active 方案 9 字段完整 / 生命周期 5 阶段齐全 / 入场后情形 ≥8 / 章节完整（h2≥8）/ 标注图存在（svg≥1）
      9-15 内容级存在性：plan-json 顶层 11 字段完整（meta/market_context/indicators/key_levels/scenario_matrix/plans/account_gate/combination_rules/risk_control/plan_traceability/plan_handover）/ active 方案 entry_reason_type / meta.data_source 为对象且含 data_time / 交付时方案状态快照节 / 交易者方程式 / 23 种入场理由矩阵 / 分析→计划映射表
      16-21：方案交接（重分析逐方案对账/首份标注无前版） / exit_rules 六件套 / position 三字段 / HTML 离场规则人读面 / 量能门槛机器可读 / JSON↔HTML 关键价一致
      22-24 形态门禁：快照节四列表格+无占位文字 / 无可见 JSON 展示块 / primary 方案块交易链表格化
      25-27 链条与图面：entry 型链条不变式（SL<带下沿<带上沿<T1 严格不等）/ manage 型方案规范 / 图面质量（chart_svg 机读属性：量能条+EMA20 全图、蜡宽≥6.5、标注框/入场带/短标计数、**时间锚定（最后K≤data_time+1根）与价签防重叠（≥16px）**）
- [ ] 任一 FAIL → 退出码 1 → 修复后重跑，**禁止带 FAIL 交付**（内容门禁全过但交付物物理不完整、缺 plan-json 顶层字段等事故固化 9-15 项；占位未回填/可见 JSON 转储/方案层纯文字等事故固化 22-24 项）
- [ ] 核对方式：脚本输出全文（全项 PASS/FAIL 明细）贴入报告"数据复核记录"节
- [ ] 附：交付前现价对表 `scripts/plan_pulse.py <报告路径>`，输出"交付时方案状态快照"写入报告；网络失败 → 如实注明数据时间戳，禁止用旧价冒充现价

## Level B（软性门禁）
- [ ] 术语双层表达；图上对象绑定（服务方案/要素）；复盘深度（回放链/模拟链/16 类错误映射）；风险提醒完整；标注克制与互锁

## 反向审读（必做，交付前最后一步）
- [ ] 从结论反向核对：对每条交易计划要素，反向找到其依据链（计划要素 → 分析章节 → Mxx → 图上对象 → DB 数据），依据链断裂的要素不得入方案
- [ ] 对每个"信号/形态/状态"结论，反向问"我凭什么这么说"：证据不足 → 降级观察或标注推断
- [ ] 用最后可见 K 线复查"当前判断"：报告结论必须站在最后一根 K 线，不得引用未发生的数据

## 复核记录（写入报告，作为通过证据）
报告末节"数据复核记录"必须列出：
- 数值核对表（数值 → 来源查询/推导 → 结果 ✓/✗）
- 关系断言核对（断言 → K 线 OHLC → 结果）
- 计数复核（H/L → 序列重算 → 结果）
- 修正记录（本次交付前发现并修正的问题清单）
- 全部 ✓ 且无未修正 ✗ 才允许交付；任一 ✗ 未修正 → 返回对应分析步骤修正。
