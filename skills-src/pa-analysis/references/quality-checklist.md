# 质量自检清单（交付前强制逐项核验）

交付前逐项检查；任何一项未通过 → 返回对应步骤修正，全部通过才输出 chip。

> **本清单是「有证据的勾选」**：每项必须给出核对方式与结果（工具返回值 / 算术重算），写不进证据的项视为未通过。可执行核对步骤见 `verification-checklist.md`。**bot 无报告、无图、无脚本** —— 原清单里「报告节 / 标注 / 图面 / 程序门禁」类项已按此删除或改写。

## 一、真实性

- [ ] 当前价 / EMA / ATR / 关键位均来自 `klines` / `indicators` / `account` 工具返回；**记下数据时间戳**
- [ ] **现价=锚点价**：所有判断以「最后一根已收盘K」为基准，禁用盘中未收盘价充当分析基准；若另示实时价，须显式区分两个时点
- [ ] **同名口径单义**：同一名称（「日高/日开/今日 OHLC」）全文单一口径；若 1d bar 口径与日内 15m 聚合口径并存（加密 7×24 品种常见），必须在首次出现处声明两套口径的取值与用途，禁止同词两值不声明
- [ ] **关键位来源精确到 bar**：价格阶梯/止损依据标注「周期 + bar 时间戳」（如「09-07 04:00 4h 高」而非「09-06 4h 高点」）
- [ ] **量能倍数口径统一=前 20 均口径**：逐处标注口径；确需「相对前一根」口径必须显式区分，**禁止同句/同段混用两种口径**（1.5× 与 3.1× 并存即口径分裂信号）
- [ ] 没有凭空补价格、补 K 线、补成交细节；无「庄家操纵/消息面必然」式不可验证依据
- [ ] 引用知识模块的判断有据可查；无法引用处标注为推断

## 二、完整性

- [ ] 四格方案（swing/scalp × long/short）齐全；每方案交易链 7 段完整；缺任何一段 → 降级为观察（不给 `open_*`）
- [ ] 每个方案要素有来源标注（来自哪条分析结论、哪个知识模块、哪个 bar）
- [ ] 形态类条件 params 硬契约：`signal_bar` / `sequence` / `momentum_check` / `risk_reward_check` **必须携带非空 params**，名字在登记词表内（见 `sequence-vocabulary.md`、`contract-enums.md`）；无参数能力的形态条件已降级为机械类条件或标注 `ai_judged: true`；语境类形态（尖峰暂停 / 通道中的棒线·二次入场 / ii最终旗形·区间陷阱 / SPS·尖峰旗形）已标注 `ai_judged: true`（对照矩阵见 `pattern-catalog_part1.md` 第五节）
- [ ] **信号K几何参数可达性复核**：params 几何阈值（`body_ratio_min` / `close_position_min` / `max_range_atr` / `tolerance_atr` 等）已用该品种近期历史 K 线分布复核**区间可达** —— 阈值超出历史分布会让 stop 计划长期 PENDING 至超时白耗窗口；复核方式（如「查近 50 根 1h，满足实体比 ≥0.6 者 7 根」）写进 `rule_ids` 说明
- [ ] 每方案含主假设 + 替代假设（主假设失效后转什么）；含证据链四段式（因为A→提出B→只有C→才D→若E失效）
- [ ] 方案组合边界：同一时刻一套主方案；同向止损重叠有加仓理由；已持有 A 时 B 出现能分类（持仓管理/加仓/反手/噪音）
- [ ] 含风险提醒（资金费率/波动率/流动性/隔夜/重大事件；外部信息与价格行为冲突时以价格行为为执行边界）

## 三、逻辑一致性

- [ ] Always In 在「市场认知/信号K/Playbook/计划方向」各处一致
- [ ] **七状态判定形式完整**：总判与分周期均用七状态枚举名（突破/窄通道/宽通道/大反转/小反转/宽区间/窄区间）；分周期禁止仅用方向词（「空头/空头转弱」）代替状态枚举名
- [ ] 核心判断方向 = 方案方向；不出现「偏多却做空」
- [ ] 触发全部落到信号K / 入场K / 跟进K / 突破回测证据，没有「上破做多/下破做空」口号
- [ ] 止损 = 假设失效位（能推翻假设），不是随手放近处高低点
- [ ] 目标 = 磁体（前高前低/中轴边界/突破点/测量移动/整数关口/趋势极值），不是「看上方/下方」
- [ ] 形态/结构/入场有据可查：每个被识别的形态能路由到 `pattern-catalog_part1.md` + Mxx，并给出失败降级；方案命名能落到 catalog 或 M51 27 规则；无法命名 → 观察
- [ ] 形态外观不压过脉络：区间中央的形态按区间处理、趋势尾端先防高潮/反转、强趋势逆势信号先当回调（M32）

## 四、风险与账户联动

- [ ] 单笔风险 ≤ 2%、总风险 ≤ 10%、杠杆 ≤ 5x（默认 1x）【阈值以执行侧 yaml 风控为唯一事实源：单笔 `risk_pct_default`、总风险 `total_risk_limit_pct`、日亏/周亏 `daily_loss_limit_pct`/`weekly_loss_limit_pct`；调参只改执行侧配置】
- [ ] 交易数学不矛盾：没有同时声称高胜率 + 高RR + 近止损 + 无需确认
- [ ] 1:1 RR 有 >50% 胜率支撑；2:1 以上有清楚止损与空间
- [ ] 胜率预期已做脉络校准：因区间/通道/强趋势下调或上调处有说明（区间中部不交易）
- [ ] 入场位置已远离失效点 → 已说明等回调/二次进场/放弃，不强行构成交易
- [ ] 目标分级与风格/状态一致：剥头皮/区间 = 单目标 100% 全平；波段 = TP1+TP2 分批（M65 §3.2 按状态取 50/30/20、25/25/50、33/33/34、50/50，剩余移动止损）；同一风格目标结构一致、合计 ≤100%
- [ ] 含入场理由匹配度判断 + 订单类型决策（限价/止损/市价）+ 风格决策（回调 K 数）
- [ ] 每个 active 方案含交易细节核验三部分：开仓理由链（≥3 条 + 来源）/ 出场规则汇总（理由→条件→动作→规则，覆盖止损/止盈/前提失效/时间/回撤/反向信号/事件）/ 仓位摘要（入场区/批/止损/止盈/张数/风险%）
- [ ] 含止损宽度决策（距离 / ATR 倍数 / 风格依据）与风控状态判定（正常/警告/熔断）
- [ ] 账户联动：无资金 / 持仓冲突 / 今日亏损超限 / 风控锁定 → 不给 `open_*`
- [ ] 仓位 = 权益 × 风险% ÷ 止损距离，分批与加仓规则符合 M65

## 五、交易生命周期（每笔交易计划的处理）

- [ ] 每个方案（含观察方案）生命周期五阶段齐全：触发前 / 触发确认 / 入场后 / 失效 / 止损后
- [ ] 未触发有明确路径：waiting→approaching→expired（离开入场区 >2×ATR 或窗口超时 → 撤单）；窄区间/信号组合否决会跳过
- [ ] 触发确认链 = 信号K收盘 → 入场K收盘 → 跟进K；触发即失效互斥检查；部分成交与立即挂止损有处理
- [ ] 入场后情形 ≥8 种，覆盖 盈利/亏损/持平/时间/事件/断连 六类；每情形有「条件→动作→规则引用」，且每条有**唯一 id**（`scenarios` 的键）
- [ ] 每个触发条件有对应失效条件（一一对应）；失效动作分级（fatal→全平/撤单，warning→减仓50%）
- [ ] 方案含质量标签（Type A/B/C），供复盘比较触发质量；**两套标签体系并用时须声明映射**：quality_tag（Type A/B/C）与信号×背景矩阵评级（A/B/C级）非同一体系，并用处须给映射说明，未声明不得同时出现两套评级
- [ ] 前提状态机：连续 3 根质疑K → 前提否定 → 立即离场（不等止损被扫）；`invalidation` 已给**数值**
- [ ] 止损被扫后：禁止追回；二次机会仅限新结构；连亏/日亏冷却；复盘记录

## 六、术语与表达

- [ ] 术语双层表达（经典术语 → 普通话 → 动作含义），无「涨不动/必然/大概率/看上方」等模糊词
- [ ] **指标精度单义**：同一指标（ATR14/EMA20）在各处引用取值精度一致，或显式声明取整规则；同一数值两套精度且未声明 → 修正后再输出
- [ ] `reasoning` ≤30 字，且不含无证据结论

## 七、复盘

- [ ] 历史复盘用回放链（当时背景→证据→逻辑→计划→失效→验证），禁上帝视角
- [ ] 每个可交易点有模拟链（当时看到什么→能否入场→止损→目标→前提失效→是否提前离场）
- [ ] 模拟按 6 问逐条回答：① 该 K 收盘前是否已足够清楚，还是必须等收盘？② 若在信号K 上方/下方入场，入场K 是否真的触发？③ 止损放在哪里说明交易假设被证明错？④ 目标来自哪个磁体？⑤ 后面哪根 K 会让原计划失效？⑥ 错过第一次入场后是否有合理二次机会？**任一问答不出 → 该点降级为训练观察点**
- [ ] 错误模式按 9 种失败模式归类，并给出教训/可复用规则
- [ ] 复盘字段对齐交易日志：七状态/Always In/背景/入场理由/信号K类型/信号质量/H1-H3/形态类型/离场理由/R倍数/错误原因/遵守规则
- [ ] 错误原因按 16 类归类（逆势/提前离场/判断错误/信号K错误/未收线入场/浮亏加仓/背景理解错误/未按计划/FOMO/心态等），与 9 种失败模式可映射
- [ ] 信息不足时使用条件性输出四段式（能判断/不能判断/需要/条件性场景），不硬写计划
- [ ] 用户圈出/框出/点名区域已单独处理（边界/角色/影响，或显式降级理由），未当作普通背景略过

## 八、返工与失败信号（输出前最后检查）

- [ ] 交易链不成链（缺任一要素）、证据链断裂、计数/数值不符 → 返回对应步骤修正，不直接输出
- [ ] 失败信号扫描：只贴形态名无背景 / 只有价位无 K 线证据 / 模糊词（涨不动/看上方/上破做多）→ 全部修正后输出

## 九、输出前自检（对应执行侧交付门禁的 plan 层 29 项）

逐条自查；**未通过项写进 `rule_ids` 的说明里**（详见 `delivery-gates.md`）：

- [ ] **RR 自洽**：`(T1 − 入场带中值) / (入场带中值 − 止损)`（空头镜像）≥ 你声明的形态基准；**RR 声明精度按实算值向下取整 0.05 档**（实算 4.72 → 声明 4.70，不虚降门槛也不越过实算）
- [ ] **订单类型语义**：入场带中值在现价**回调侧** → `limit`；**突破侧** → `stop`/`stop_limit`；触发含突破族 sequence（`breakout_ignition`/`quality`/`pullback`、`pbt`、`trend_line_breakout`）→ 必须 `stop`；措辞约定：信号K确认版突破回撤写「突破回撤/BOP/PBT」，「回测/回踩」专指限价接货
- [ ] **失效处理对应**：每条失效条件都有对应处置（漏接 = 触发后无人接管）
- [ ] **四格矩阵**：覆盖 swing/scalp × long/short；缺失格须显式申报豁免理由（style + direction + reason）
- [ ] **占位清零**：任何字段不留「X点 / 待填 / TBD / TODO」，也不留**数字+xx 模糊占位**（「78,3xx」式写法）；数值一律写精确值
- [ ] **时间口径**：`time_stop_bars` 与风格自洽（swing 不用分钟级叙事；scalp 时间止损应短）
- [ ] **链式不变式**：多头 `止损 < 入场带下沿 < 带上沿 < T1`（严格不等），空头镜像 —— **相等即断裂**
- [ ] **前提失效位**：`invalidation` 是数值；**空头方案语义是「收盘站上」**（写反方向 = 永不失效或秒失效）
- [ ] **止损距离**：`|止损 − 入场带中值| ≥ 0.5 × ATR`（ATR 取方案执行周期：swing→1h、scalp→5m）；不足即「噪声扫损侧」
- [ ] **逆势仓位**：逆 Always In 的方案风险减半，或给出趋势线突破依据
- [ ] **失效条件词表**：共识类失效条件的 `expected` 只写 `long`/`short`/`neutral`（禁 `ais`/`ail` 缩写 —— 会让条件永久不成立）
- [ ] **逆AIL 结构互斥**：逆势方案的共识类失效条件**不得**写成「入场时的 AIL 值」—— 那会让条件在入场瞬间已成立、永不构成「翻向」。改写为「入场锚 + 转移」表述，或改用价格/时间类失效条件
