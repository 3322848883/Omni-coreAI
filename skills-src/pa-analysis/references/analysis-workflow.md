# 分析工作流（每步三元约束）

> 每个步骤按"输入 → 处理 → 通过标准 → 失败处理"四段执行。不满足通过标准时，按明确的失败路径降级，不临时发明新分支。

## 前置步骤：方案交接（重分析必做；首份报告跳过并标注"无前版"）
> **机械层已由预检管线覆盖（2026-09-10）**：扫最新旧报告/提取 plan-json/plan_pulse 机械状态 = `analysis_preflight.py` S2（范围硬封顶=仅最新一份），产出 `preflight.md` 交接候选对账表；**AI 不再写任何交接核查脚本**，只做下述四选一定案判断（= state 的 handover_review 阶段），定案结论落盘 `handover_decision.md`。
- **输入**：`outputs/` 下同品种最新报告（`{symbol}-analysis-*.html`，按文件名日期 + meta.generated_at 取最新）。
- **处理**：提取旧报告内嵌 plan-json（读文件，不靠会话记忆——换会话仍可执行）；可先运行 `scripts/plan_pulse.py <旧报告>` 取得旧方案对现价的机械状态（已进入场区/已破失效位/仍在等待）；然后对旧 plans 数组**逐方案**四选一定案——①已触发（转 L6 复盘链）/ ②已失效（归档，注明失效价与时间）/ ③继续等待（原样并入新报告并在 quality_tag 注明"延续自 YYYY-MM-DD 版"）/ ④结构已变（supersede：新方案替代，归因一句话——行情演化（数据驱动）还是判断修正（分析驱动））。对账表写入新报告"方案交接"节；机器可读形式为 plan-json 顶层 `plan_handover` 字段（见 plan-schema.md）。
- **通过标准**：对账表覆盖旧报告 plans 数组的每一个 plan_id（含 watch 方案），无遗漏、无静默丢弃；每个结局有一句话依据（价格证据或结构理由）；超龄方案（scalp>30 分钟/swing>4 小时，参照节点3 G11）结局归"已失效-过期"并注明；首份报告有"无前版"标注。
- **失败处理**：旧报告 plan-json 解析失败 → 以旧报告正文方案节为对账基准并在新报告注明降级；找不到旧报告 → 按首份处理并在工作目录记录检索过程；旧方案结局无法判定（价格未到任何结构位）→ 归"继续等待"并复核其过期边界。

## 步骤 0：确认输入与事实源
> **已由预检管线 S1 覆盖（2026-09-10）**：K 线时效表（5 周期最后K/年龄/STALE 标记）+ 当日日线 + 隔夜高 + 账户快照（余额/持仓/挂单/当日盈亏）+ node1 健康，全部见 `preflight.md`；AI 直接引用，不再现写查询。
- **输入**：节点1 数据库（data/kline.db：OHLC/ema20/atr14；data/account.db：balance/position/order）或用户图表截图/OHLC。
- **处理**：确认品种、周期、数据时间范围与新鲜度；只以这些数据为事实源。
- **通过标准**：能给出当前价格、最新 K 线时间、数据来源路径；账户状态（余额/持仓/今日盈亏）可读。
- **失败处理**：数据缺失或过期 → 先补拉节点1 数据；用户图表 → 以图表为唯一事实源，不凭空补价格；信息不足会编造时，先问最少的关键问题。

## 步骤 1：走势分段草稿
- **输入**：当前周期最近 80-160 根 K 线（决策侧重最近 20-30 根）——特征读数取自预检产物 `fs_{1d,4h,1h,15m,5m}.md`（L0 窗口摘要+L1 最近20根+L2 最近5根，冻结库同源唯一一轮，禁止重复生成）。
- **处理**：从左到右切 5-7 段，每段一句话：这段是什么 → 谁在控制 → 为什么 → 交易动作怎么变。给每段分配角色：背景段 / 状态切换段 / 控制权切换段 / 当前决策段 / 可移正文段。
- **通过标准**：每段能说清控制权在哪切换；标注可追溯到段落。
- **失败处理**：说不清控制权或证据的段落 → 不上图、只入正文或删除；分段无法覆盖最后一根可见 K 线 → 重读图。

## 步骤 2：状态决策树化
- **输入**：分段草稿 + 七状态（突破/窄通道/宽通道/小反转/大反转/宽区间/窄区间）判定要素。
- **处理**：把模糊判断拆成可复查节点（突破后有没有跟进？距离是否足够远？不利影线是否超过实体一半？回撤是否进入磁体射程？）。每节点只产生明确分支：做 / 等 / 缩仓 / 改目标 / 删除。参数必须可复查（20 缺口棒必须数 K；急赴磁体必须量距离；区间突破回调必须确认跟进）。
- **周期切换信号（每次切换必列）**：每次状态切换必须指出当时已能看到的 K 线信号，例如 连续 2-3 根同向强 K、突破后跟进、K 线重叠突然增加、强反向 K 收在极端位置、逆势方开始轻松赚钱；无信号证据的切换不成立。
- **阶段不明按保守侧处理**：无法在七状态中定位时，按更保守的一侧处理（如"可能区间可能通道"→ 按区间边界交易或观察），并标注"阶段不明，按保守侧"。
- **通过标准**：状态判定有可复查参数支撑；分支无"看感觉"。
- **失败处理**：只差一点满足规则（如 19 根不等于 20 根）→ 默认不交易，可标注"接近条件"但不当作已触发；动态读图暴露规则盲区 → 复盘后改规则，当下不发明新分支。

## 步骤 3：逐根读取
- **输入**：最近一段 K 线（重点最近 20-30 根）。
- **处理**：每根至少判断：实体长短、收盘位置、影线、与前几根关系（推进/重叠/回测/停顿/反向突破）、后续跟随。单根先分两类：趋势 K（实体明显；顺势=动能延续，破位=看跟进）与区间 K（影线重叠明显；区间内=停顿，边界=看失败突破/反转）。外观暧昧时服从脉络。
- **通过标准**：只标注会改变计划的 K（突破 K、信号 K、失败突破 K、回测失败 K、加速 K、停顿 K）；其余判断留在证据链。
- **失败处理**：图面放不下逐根标注 → 关键 bar 复盘放正文；原图无编号时不新增编号。

## 步骤 4：运动分段与数推
- **输入**：走势分段草稿。
- **处理**：用四个标准分段：阴阳交替（一串同向 K=一方持续控制，颜色切换=断点）；回调 K（低点下移/高点抬高=对方造成回调）；显著高低点连线（连接每推最远端确认轮廓）；规模匹配（时间间距与振幅同级）。二推失败≈双顶底、三推失败≈楔形；多数波段在顺势二推/三推后出现止盈/回调/小型反转。
- **通过标准**：推数分段能对应波段和趋势层级，并标出第一推/第二推/第三推。
- **失败处理**：规模不匹配的过细/过粗分段 → 合并或拆分；推数无法确认 → 只标趋势不标推数。

## 步骤 5：交易日准备（磁体与波幅）
- **输入**：前一交易日数据/日线（如有）+ 当前图。
- **处理**：用 ATR（无则用近日平均波幅/前日高低）估计今日可能波幅；在波幅内向左找磁体：前一日高低收、当日开盘、明显前高前低、突破后跟进的回调高低点、开盘区间上下沿、历史新高新低；只保留会改变行为的 3-6 个磁体；开盘前几根强双边争夺 → 标开盘区间，若区间高度远小于平均波幅，预期突破/扩张。
- **通过标准**：每个磁体有用途（目标/触发/失效/观察反应/不交易理由）。
- **失败处理**：超出波幅太远、未被接近、只会让图变乱的线 → 删除。

## 步骤 6：建仓方案设计（价格行为理据 + 交易数学）
- **输入**：状态判定 + 逐根证据 + 磁体。
- **处理**：每个建仓方案必须同时满足：① 价格行为理据（为什么此处有人愿意买卖、谁被困、谁止盈止损、哪些磁体作用）；② 交易数学（入场/止损/目标/胜率假设/盈亏比/风格匹配）。方案类型按 `references/pattern-catalog.md` 全表 + M51 27 条规则选择：收线追进、首次逆势失败后顺势恢复、双顶底旗形、楔形旗形、区间边界短打、突破回测（BOP）、H2/L2 二次进场、急赴磁体、通道尾端反转、均线缺口、缺口K线、ii/iii/ioi、最终旗形、高潮反转、失败之失败、头肩顶、扩张三角、DBL/DBS、决斗线等；方案命名必须能落到 catalog 或 M51 规则。处理顺序：先定脉络 → 再定方案 → 再定离场（此处即产出 exit_rules 六件套：硬止损价/止盈分批/M13七层按方案风格定参/时间止损 swing 24h重估+72h全平、scalp 45min减半+90min全平 或按方案的 K 线计数规则/峰值回撤50%/前提否定打平）→ 再定删除条件。
- **输出即完整（硬约束）**：方案设计完成时，plan 全字段必须一次齐全——分析位（entry_zone/entry_trigger/entry_reason_type/stop_loss/take_profit/position）+ 执行位（exit_rules 六件套）+ lifecycle 骨架；缺任何字段 = 方案未完成，不得进入下一步，更不得交付。节点2 是大脑：完整方案在分析中产出，交付后无补丁。
- **通过标准**：只有统计现象没有价格行为解释，或只有故事没有止损/目标/期望约束 → 都不能直接用；方案能命名、能给出完整交易链、全字段齐（对照 plan-schema.md 单方案结构清单）。
- **失败处理**：无法命名交易假设或逻辑说不清 → 降级为观察计划；方案撞不利磁体/路径被挡/跟进失败/数学失衡 → 删除或降级；离场规则某件套定不出参数（如无明确前提否定条件）→ 该方案降级观察，不得带空壳交付。

## 步骤 7：交易数学与风格校准
- **处理**：交易是否值得 = 成功概率×潜在回报 > 失败概率×风险。胜率与盈亏比通常反向。1:1 RR 需明显高于五成胜率；2:1 可接受更低胜率但止损清楚、空间足够；3:1 以上不默认高胜率。一个计划同时声称高胜率+高RR+近止损+无需确认 → 假定估算错误。等距校准：均衡≈50%；强趋势顺势 1R 按 60% 上限，逆势按 40% 或更低。风格：波段（2R+，10-30 根 K，急速/窄通道/强趋势）；剥头皮（1R 或以下，1-5 根 K，宽通道/区间边界/磁体/均线回归）。强趋势中的逆势剥头皮默认删除（新手）。
- **通过标准**：每方案有胜率/RR/风格一致；数学不矛盾。
- **失败处理**：止损无法定义 → 不构成可执行交易；入场远离失效点 → 等回调/二次进场/放弃；数学失衡 → 删除或缩仓。

## 步骤 8：知识引用
- **处理**：每步分析引用对应知识模块（Mxx）或指南章节（见 SKILL.md 知识路由表），注明引用来源。
- **通过标准**：关键判断（状态/信号/形态/概率/入场规则）有知识依据可查。
- **失败处理**：无法引用知识依据的判断 → 标记为推断，不写成事实；存疑处降级处理。

> **范围边界**：本文件只展开分析阶段（前置+步骤 0-8）。报告生成阶段的步骤（标注图渲染 / HTML 双骨架 / 质量清单 / 数据复核 / 现价对表 / 物理验证）以 SKILL.md 工作流总览步骤 5-10 为准；**auto 模式差异**：charts 阶段 skipped、html 阶段为 plan-shell 壳装配、validate 用 `--profile plan`（见顶部九阶段映射表）；K 线图渲染的唯一规范是 `references/annotation-spec.md` 绘制工具链（唯一渲染器 `scripts/chart_svg.py` + 时间锚定 end=data_time + 防重叠），不在本文件展开。
