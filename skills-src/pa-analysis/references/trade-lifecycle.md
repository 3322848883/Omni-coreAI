# 交易生命周期处理规范（每笔交易计划的处理）

> 优化依据：本规范整合交易系统执行层（状态机/动作/规则族）与参考技能（证据链/失效降级/二次机会/复盘链）的已验证优化点，不替换本体系的术语、知识资产与契约。
> 原则：每个方案的每个阶段都写"输入 → 处理 → 通过标准 → 失败处理"；说不清某一阶段怎么处理 → 该方案降级观察（active=false）。

## 订单类型 × 挂单时序（预挂架构 · 2026-09-12）

节点3 已按 order_type 分流布防时序（spec: preplace-entry-architecture D1-D4，详见 `plan-schema.md`「订单类型 × 挂单时序」），本规范阶段 0/1 的适用范围随之分化：

| order_type × 触发条件构成 | 阶段 0（触发前） | 阶段 1（触发确认） |
|---|---|---|
| `limit` | **无等待语义**——布防即直挂 GTC 梯次，价格打到即成交 | 不适用（无确认链）；触发条件仅作计划质量自核叙事 |
| `stop`/`stop_limit` 且 trigger 含 signal_bar/sequence | 布防后等待信号K 确认（confirm-then-place，信号K 另一端 1 tick 挂触发单） | 适用——信号K 收盘确认即挂单；其余条件（共识/RR/市场状态/量能）转观察数据，由本规范+validate 门禁在交付侧把关 |
| `stop`/`stop_limit` 且纯价格类触发 | 无等待语义——布防即直挂触发单 | 不适用（价格触发即成交） |

- 撤单只认失效条件（fatal 失效线/计划到期），信号K 不参与撤单（D2）；SL/TP 与入场单同批预挂且成交后持续核验（D3）。
- 方案叙事须与所选 order_type 的时序一致：limit 方案写「回踩接货、布防即挂」，stop 方案写「信号K 确认后追认突破」——禁止 limit 方案叙事「等全条件确认」、stop 方案叙事「提前挂单接回调」。

## 阶段 0：触发前（未触发怎么处理）
- **输入**：方案触发条件（信号K/入场K/跟进K + 入场区 + AIL 共识）+ 节点1 实时数据。
- **处理**（对齐 plan_watcher 状态机）：
  1. `waiting`：价格未进入入场区，按监控间隔检查（默认 5 分钟）。
  2. `approaching`：价格距入场区 ≤ 0.3×ATR，提高检查频率（默认 1 分钟）。
  3. `expired`：价格离开入场区超过 2×ATR 且未触发 → 计划过期，撤单 + active=false + 记录"未触发观察"。
  4. 窗口超时：挂单/等待窗口结束（swing 4-8 小时、scalp 45 分钟）仍未触发 → 撤单，等待新信号；不允许无限期挂单。
  5. 状态否决：市场状态变为窄区间/铁丝网 → 自动跳过全部计划（Playbook 过滤）；信号组合评估为 none/conflict → triggered 修正回 waiting，不触发。（**预挂架构注记**：此条为节点2 分析侧过滤与 AI 巡检侧否决；节点3 运行时市场状态类条件不拦截已布防订单，仅入快照观察）
  6. 接近但未满足：条件只差一点（如信号K实体差 2 点、H2 只有 H1）→ 不触发，标注"接近条件"，但不当作已触发（M02）。
- **通过标准**：每个触发条件都有"未满足怎么办"（等待/降级/清除）和对应的失效条件；未触发路径不会留下永续挂单。
- **失败处理**：说不清未触发怎么处理、或没有超时/清除规则 → active=false。

## 阶段 1：触发确认（触发时的核对）
> **适用范围（预挂架构）**：仅 `stop`/`stop_limit` 且 trigger 含 signal_bar/sequence 的方案（见「订单类型 × 挂单时序」）；limit 与纯价格 stop 布防即挂，无本阶段。
- **输入**：触发条件全部满足时的最后 1-3 根 K 线。
- **处理**：
  1. 信号K 收盘确认 → 入场K 收盘确认（≥ 信号K 极值）→ 跟进K 不破信号K 低点/高点。
  2. 触发瞬间同时检查失效条件：触发即失效（如信号K 收盘同时破双底）→ 取消入场，不做"先入再撤"。
  3. 部分成交：分批 50/30/20 中部分批次未成交 → 按已成交仓位执行；未成交批次作废，不补挂；若因滑点未成交且价格已走远 → 放弃。
  4. 触发后立即设置硬止损（SL-01/SA-07：信号K 极值外 1 tick 或假设失效位），禁止"等确认再设"。
- **通过标准**：触发链可复查（哪根是信号K/入场K/跟进K）；触发与失效互斥检查完成；止损已挂。
- **失败处理**：无法识别信号K/入场K/跟进K → 不触发；触发链缺跟进 → 降级观察。

## 阶段 2：入场后情形处理（每笔交易必含情形表）
> 每个方案必须给出 ≥8 种情形；每情形 = 条件 → 动作 → 规则引用。情形与方案要素（止损/目标/时间/仓位）一一对应。

| # | 情形 | 条件 | 动作 | 规则引用 |
|---|------|------|------|---------|
| 1 | 浮亏 0–1R，前提未受质疑 | 价格反向但结构未破坏 | 持有至止损，不手动干预 | M66 假定持平 / BAN-03 |
| 2 | 前提被质疑（1–2 根质疑K） | 趋势线破/回撤过深/信号K 被破 | 减仓 50%（reduce_position），保留剩余 | premise_state_machine QUESTIONED / PM-05 |
| 3 | 前提被否定（连续 3 根质疑K） | 结构失效 | 立即离场（不等止损被扫） | premise_state_machine INVALIDATED / EX-05 |
| 4 | 快速盈利 +1R | 盈利达 1R | 平 50%（scalp 全平），剩余止损移至保本 | PP-01 / PP-04 / SA-02 |
| 5 | 盈利 +2R | 盈利达 2R | 止损移至 +1R；测量目标附近减仓 | SA-03 / EX-02 / EX-09 |
| 6 | 触及磁体 | 价格到达目标磁体 | 获利了结优先，剩余收紧止损；不反向建仓除非强信号 | EX-03 / M37 |
| 7 | 强反向信号K | 出现大实体反向K/上影或下影极端 | 平仓或收紧至保本 | EX-04 |
| 8 | 突破回撤失败 | 突破后回撤超过关键位/回撤过深 | 减仓或离场；转反向观察 | FM-06 / FM-09 |
| 9 | 时间止损 | scalp 15–45 分钟 / swing 45–90 分钟未达目标 | 减仓 50% → 全平 | SL-06 / EX-07 / M66 |
| 10 | 回撤止损 | 浮盈回撤 50% | 立即平仓 | M13 第 7 层 |
| 11 | 加仓条件 | 高概率回撤 + 距首批 ≥1R + 总风险不变 | 允许加仓（最多 2 次）；否则不加 | PM-04 / M65 2.3 |
| 12 | 减仓条件 | 低概率形态/信号质量降级/不确定 | 减半或跳过 | PM-05 |
| 13 | 重大事件 | 数据/事件前后 5 分钟 | 不开新仓；持仓减半或平仓 | RM-06 / M27 #5 |
| 14 | 数据源中断 | 节点1 断连/数据过期 | 挂单保留、停止新单；持仓动作转人工核对 | 节点1 健康检查 |
| 15 | 滑点/部分成交异常 | 市价滑点 > 2 tick / 部分成交异常 | 记录并停止追单 | RM-04 |
| 16 | AIL 共识破坏 | swing AIL < 3/5；scalp 周期 AIL 翻转 | swing 减仓 50%；scalp 全平 | M20 / invalidation |

- **市况定档（pe9 补充）**：time_stop 档位随 market_context 调整——铁丝网/宽区间/震荡市况收紧 at_hours（僵尸单快出），强趋势/窄通道放宽（容忍回调，结构不破不止损）；condition 一律条件式（「未达目标/未盈利」），禁止「无论盈亏」表述。config 兜底档仅在计划未提供 time_stop 时保底。
- **通过标准**：情形表覆盖"盈利/亏损/持平/时间/事件/断连"六类；每个动作有对应规则与计划要素。
- **失败处理**：情形表缺 ≥2 类 → 该方案不输出入场。

## 阶段 3：失效（Invalidation）处理
- **输入**：方案 invalidation_conditions（fatal/warning 分级）。
- **处理**：
  1. 一一对应原则：每个触发条件必须有对应失效条件（触发"信号K收盘确认" ↔ 失效"信号K被破/无跟进"；触发"回踩不破双底" ↔ 失效"收盘破双底"）。
  2. 动作分级：fatal → 撤单/全平，立即执行；warning → 减仓 50% 或收紧止损，继续观察。
  3. 前提状态机：PENDING → VALIDATED / QUESTIONED → INVALIDATED（连续 3 根质疑K → 否定 → 离场）。
  4. 删除条件 = 计划不再成立：撤单 + active=false + 记录原因（转观察/转反向激活）。
  5. 离场优先级：硬止损 > 反转信号 > 目标 > 失效 > 时间 > 回撤（M66 离场信号优先级）。
- **通过标准**：每个失效条件能回答"触发后做什么、剩余仓位怎么办、是否转观察/反向"。
- **失败处理**：失效条件无动作或无对应触发 → 该条件删除，方案重新评估。

## 阶段 4：止损被扫 / 离场后
- **输入**：离场原因（止损/目标/失效/时间/回撤）+ 成交记录。
- **处理**：
  1. 禁止追回：同一信号/同一位置不二次追单（BAN-11 报复交易；BAN-12 移动止损远离入场价）。
  2. 二次机会判断：仅当市场形成新结构（新 H2/新信号K/新双底顶）才允许新计划；同一位置重复入场禁止（参考技能：错过第一次入场，后面是否有合理二次机会）。
  3. 连亏/日亏更新：连续亏损 ≥3 → 冷却 30 分钟；日亏超每日限额（config daily_loss_limit_pct）→ 当日停止（RM-01/03）。
4. 复盘记录（节点4）：离场原因、执行质量、MAE/MFE、九类失败归类、当时证据链。
5. 可复用规则沉淀（节点5）：新规则需"当时背景→证据→逻辑→计划→失效→验证"完整链。
- **通过标准**：离场后动作明确（禁追回 + 二次机会条件 + 复盘 + 冷却），不产生报复性再入场。
- **失败处理**：无法说明为何离场 / 离场后无纪律约束 → 该交易标记为失败样例，进入复盘。

### 复盘字段（借鉴交易系统交易日志 pa-trading-journal.xlsx）
每笔平仓交易的复盘记录对齐交易日志 31 列，报告复盘层/节点4 至少覆盖：
- 基本信息：日期/品种/周期/七状态/Always In/背景备注
- 入场：入场理由/方向/入场价/仓位/入场方式/订单类型/入场前心态/持仓中心态
- 信号评估：信号K类型/信号质量/**H1/H2/H3**/形态类型
- 离场：离场价1/离场价2/离场理由/离场方式
- 结果：盈亏(USDT)/状态/累计盈亏
- 复盘：入场前检查（计划/信号/风险/心态四勾）/R倍数/错误原因/遵守规则/备注
- **错误原因按交易日志"错误统计"16 类归类**：逆势交易 / 盈利单提前离场 / 突破反转判断错误 / 错误信号K / 限价单入场问题 / K线未收线入场 / 阻力买支撑卖 / 浮亏加仓 / 市场背景理解错误 / 未按计划执行 / 过度交易 / FOMO追单 / 订单类型错误 / 入场前心态不佳 / 持仓中心态失控 / 未做入场前检查（与九类失败模式兼容，可双向映射）
- **入场理由分析**：按 23 类入场理由 + 七状态 + 形态类型（趋势延续/反转/突破/假突破/回调/区间交易）统计胜率与平均 R，供节点5 校准。

## 报告呈现（L4 交易计划层内）
每个 active 方案在 7 段交易链之后，必须附"交易生命周期"表：

| 阶段 | 处理 | 规则引用 |
|------|------|---------|
| 触发前（未触发） | waiting→approaching→expired；窗口超时撤单；状态否决 | plan_watcher 状态机 |
| 触发确认 | 信号K→入场K→跟进K；触发即失效互斥；止损立即挂 | M02 / SL-01 |
| 入场后（情形表） | ≥8 情形（条件→动作→规则） | 阶段 2 情形表 |
| 失效 | fatal 全平 / warning 减仓；前提状态机 | premise_state_machine |
| 止损后 | 禁追回；二次机会条件；复盘+冷却 | BAN-11 / RM-01/03 |

## 内嵌 JSON（节点3 契约）
每个方案的 plan-json 增加 `lifecycle` 对象（字段见 plan-schema.md），节点3 的 plan_watcher/position_manager 据此监控：
- `pre_trigger`：wait/approach/expire 规则（与 plan_watcher 状态机对齐）。
- `post_entry_scenarios`：情形表，每条四要素（id→level→condition→action，rule_ref 可选；id 非空且计划内唯一，level ∈ auto/semi/log 与节点3 执行通道对齐——validate_report 第 41 项把关）。
- `invalidation_handling`：失效→动作映射（fatal/warning）。
- `after_stopout`：禁追回 + 二次机会条件 + 复盘节点。
