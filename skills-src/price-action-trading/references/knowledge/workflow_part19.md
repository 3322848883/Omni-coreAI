## 交易闭环：从分析到结束的完整生命周期

> 一次完整的交易闭环 = 首次分析 → 计划制定 → 持续监控 → 执行交易 → 持仓管理 → 平仓复盘。
> **强制要求**：一旦生成交易计划（订单上下文（活跃计划） 活跃计划状态 = 等待触发），后续每次分析都必须走路径A1/A2/D进行持续监控，直到计划状态变为"已触发"或"已失效"或"已过期"。禁止在计划有效期间跳过监控直接生成新计划。
> 每次用户请求"分析行情"都是闭环中的一个检查点，不是独立的分析。

### 闭环阶段定义

```
┌─────────────────────────────────────────────────────────────────┐
│ 阶段一：发现机会（路径C — 首次分析）                              │
│   Step 0.5a → Step 0.5b(无计划) → 完整 Step 1-6               │
│   → 生成交易计划（方案A/B）→ 写入 订单上下文（活跃计划）                │
│   → 写入 决策日志 → 等待用户下次请求                      │
│   状态：计划 = 等待触发                                          │
├─────────────────────────────────────────────────────────────────┤
│ 阶段二：等待触发（路径A1 — 持续监控）                            │
│   用户请求分析 → Step 0.5a → Step 0.5b(计划有效)               │
│   → Step 1 快速更新（市场状态未变）→ "计划未变，继续等待"          │
│   → 更新 订单上下文（活跃计划） 价格 → 写入 决策日志             │
│   状态：计划 = 等待触发（不变）                                   │
│   重复：每次用户请求都走 A1，直到：                               │
│     a) 价格触及触发条件 → 进入阶段三                              │
│     b) 市场变化导致计划需调整 → 进入阶段二变体                     │
│     c) 市场变化导致计划失效 → 回到阶段一                          │
├─────────────────────────────────────────────────────────────────┤
│ 阶段二变体：计划调整（路径A2）                                    │
│   Step 0.5a → Step 0.5b(计划需调整) → Step 1+3                │
│   → 调整计划参数（止损/目标/触发条件）→ 写入 订单上下文（活跃计划）     │
│   → 写入 决策日志 → 回到阶段二继续等待                     │
│   状态：计划 = 等待触发（参数已更新）                             │
├─────────────────────────────────────────────────────────────────┤
│ 阶段三：执行交易（路径B→D — 下单）                               │
│   Step 0.5a → Step 0.5b(计划有效) → Step 1-6 确认入场条件满足   │
│   → Step 6.5 场景B → HC-01~10 通过 → 获取持仓模式               │
│   → 提交入场单 + 止盈触发单 + 止损触发单                         │
│   → 写入 订单上下文（先执行后写入）                            │
│   → 更新 订单上下文（活跃计划）（计划状态 → 已触发）                     │
│   状态：计划 = 已触发 → 持仓中                                   │
├─────────────────────────────────────────────────────────────────┤
│ 阶段四：持仓管理（路径D — 持续监控持仓）                          │
│   用户请求分析 → Step 0.5a(有持仓) → Step 0.5b → 路径D          │
│   → Step 1 快速更新（方向是否一致）                              │
│   → Step 7 持仓管理（TS-01~05）：                               │
│     • 止损未触发 → 保持                                          │
│     • 达1R盈利 → 止损移至保本（SA-02）                           │
│     • 达2R盈利 → 平50%+止损移至1R（SA-03+PP-01）                │
│     • 创新高/低 → 追踪止损（TS-02）                              │
│     • 方向不一致 → 评估平仓                                      │
│   → Step 6.5 场景D 执行操作                                     │
│   → 写入 订单上下文 阶段三（修改记录）                        │
│   → 更新 订单上下文（活跃计划） + 决策日志                       │
│   状态：持仓中（止损/目标持续更新）                               │
│   重复：每次用户请求都走 D，直到：                               │
│     a) 止盈触发 → 进入阶段五                                    │
│     b) 止损触发 → 进入阶段五                                    │
│     c) 手动平仓 → 进入阶段五                                    │
├─────────────────────────────────────────────────────────────────┤
│ 阶段五：平仓闭环（路径D 平仓）                                   │
│   止盈/止损/手动平仓触发 → Step 6.5 场景D 平仓操作              │
│   → 写入 订单上下文 阶段四（平仓记录+完整交易总结）            │
│   → 写入 决策日志（复盘）（复盘分析）                            │
│   → 更新 决策日志（设置胜率）（胜率）                │
│   → 更新 决策日志（错误模式）（如有BAN违规）                 │
│   → 更新 决策日志（改进项）（改进计划）               │
│   → 更新 决策日志（策略假设）（假设验证）              │
│   → 更新 订单上下文（活跃计划）（持仓状态清空，活跃计划 → 已成交）      │
│   状态：交易闭环完成                                              │
├─────────────────────────────────────────────────────────────────┤
│ 阶段六：再决策（CD-01~05）                                      │
│   平仓后 → 判断是否继续交易：                                    │
│   • CD-01 冷却期（15-30分钟）→ 不写入，等待                     │
│   • CD-02 评估 → 更新 决策日志                       │
│   • CD-03 同向再入场 → 回到阶段一（新计划）                     │
│   • CD-04 反向交易 → 回到阶段一（新计划）                       │
│   • CD-05 观望 → 不写入，等待下次分析                           │
└─────────────────────────────────────────────────────────────────┘
```

### 闭环状态机

| 当前状态 | 触发条件 | 下一状态 | 执行路径 |
|---------|---------|---------|---------|
| 无计划 | 用户请求分析 | 等待触发 | C（完整分析→新计划） |
| 等待触发 | 用户请求分析+市场未变 | 等待触发 | A1（快速更新→不变） |
| 等待触发 | 用户请求分析+需调参 | 等待触发(已更新) | A2（调参→继续等待） |
| 等待触发 | 用户请求分析+计划失效 | 无计划 | B（完整分析→新计划） |
| 等待触发 | 价格触及触发条件 | 已触发 | B→D（下单→持仓管理） |
| 已触发(持仓中) | 用户请求分析+方向一致 | 已触发(持仓中) | D（持仓管理） |
| 已触发(持仓中) | 止盈/止损触发 | 已成交 | D（平仓→复盘→记忆更新） |
| 已成交 | CD-03同向再入场 | 等待触发 | C（新计划） |
| 已成交 | CD-04反向交易 | 等待触发 | C（新计划） |
| 已成交 | CD-05观望 | 无计划 | 等待下次分析 |

### 用户在闭环中的角色

| 环节 | AI 自动执行 | 需要用户操作 |
|------|-----------|-------------|
| 分析行情 | ✅ Step 0-6 全自动 | 发起"分析行情"请求 |
| 计划制定 | ✅ 自动生成方案A/B | 无 |
| 持续监控 | ✅ 每次请求自动走A1/A2/D | 定期发起请求 |
| 下单执行 | ✅ HC通过后自动三单 | 无（全自动模式） |
| 持仓管理 | ✅ TS-01~05自动管理 | 定期发起请求 |
| 平仓 | ✅ 止盈止损自动触发 | 无 |
| 复盘 | ✅ 自动生成复盘+更新记忆 | 无 |
| 再决策 | ✅ CD-01~05自动判断 | 无 |

> **用户唯一需要做的**：定期发起"分析行情"请求。AI 根据当前闭环状态自动走对应路径。
> 建议频率：有持仓时每15-30分钟请求一次，无持仓时每1-4小时请求一次。
> **监控强制性**：有活跃交易计划时，每次分析请求必须执行 Step 0.5b 计划衔接检查。不得以"用户未要求"为由跳过计划监控。计划的生命周期（等待触发→已触发→已成交 或 等待触发→已失效）必须被完整追踪。阶段二和阶段四中的所有监控场景（共15个）为强制检查项，每次分析必须逐一评估。
