# 分析连续性与时间判断规则

> 确保每次分析都利用历史数据，避免独立分析问题。

## 一、分析前必读文件

### Step 0（记忆检索）执行清单

```
1. 读取 market_state.md
   - 检查分析时间
   - 获取上次市场状态
   - 获取持仓状态（如有）
   - 获取关键价格位

2. 根据时间间隔决定处理方式
   - < 15 分钟: 直接使用上次分析，更新价格
   - 15-60 分钟: 读取上次分析，重新评估信号棒
   - 1-4 小时: 读取上次分析，重新执行 Step 1-3
   - > 4 小时: 完全重新分析
   - 跨日: 完全重新分析

3. 读取最近 3 次分析记录（logs/analyses/）
   - 获取历史分析结论
   - 识别市场状态变化
   - 检查是否有持仓

4. 读取记忆文件（如有数据）
   - pattern_effectiveness.md: 设置有效性
   - error_patterns.md: 错误模式
   - trader_profile.md: 个人画像
   - market_wisdom.md: 市场智慧
```

## 二、分析后必写文件

### 更新清单

```
1. 更新 market_state.md
   - 更新分析时间
   - 更新当前价格
   - 更新市场状态
   - 更新 Always In 方向
   - 更新持仓状态（如有）
   - 更新关键价格位

2. 写入 logs/analyses/
   - 文件名: YYYY-MM-DD_HHMM_btc.md
   - 内容: 简化版分析结论

3. 写入 logs/orders/（如有交易）
   - 文件名: YYYY-MM-DD_HHMM_btc_short.md
   - 内容: 订单详情

4. 更新记忆文件（如有新数据）
   - pattern_effectiveness.md: 更新设置胜率
   - error_patterns.md: 记录错误模式
   - market_wisdom.md: 记录市场规律
```

## 三、时间判断规则

### 时间间隔处理矩阵

| 时间间隔 | 市场状态 | 信号棒 | 止损校验 | 交易者方程 | 处理方式 |
|---------|---------|--------|---------|-----------|---------|
| < 15 分钟 | 复用 | 复用 | 复用 | 复用 | 直接使用，更新价格 |
| 15-60 分钟 | 复用 | 重新评估 | 复用 | 复用 | 读取上次，评估信号棒 |
| 1-4 小时 | 重新分析 | 重新评估 | 重新校验 | 重新计算 | 重新执行 Step 1-3 |
| > 4 小时 | 重新分析 | 重新评估 | 重新校验 | 重新计算 | 完全重新分析 |
| 跨日 | 重新分析 | 重新评估 | 重新校验 | 重新计算 | 完全重新分析 |

### 跨日判断

- 定义: 上次分析日期 ≠ 当前日期
- 处理: 完全重新分析，不使用任何上次数据
- 原因: 日线级别数据已更新，HTF 状态可能改变

### 波动率变化判断

- 定义: 当前 ATR / 上次 ATR > 1.5 或 < 0.7
- 处理: 重新校验止损和仓位
- 原因: 波动率变化影响止损距离和仓位大小

## 六、记忆文件更新规则

### pattern_effectiveness.md

- 更新时机: 每笔交易完成后
- 更新内容: 设置类型胜率、最佳/最差条件
- 数据来源: logs/orders/

### error_patterns.md

- 更新时机: 检测到规则违反时
- 更新内容: 错误类型、发生频率、根因分类
- 数据来源: 分析过程中的 BAN 触发

### market_wisdom.md

- 更新时机: 发现新的市场规律时
- 更新内容: 规律描述、适用条件、置信度
- 数据来源: 分析过程中的观察

### trader_profile.md

- 更新时机: 每月回顾时
- 更新内容: 优势市场、情绪模式、认知偏差
- 数据来源: 累计交易数据

## v33 新增：5路径分流规则

> Step 0.5.4 计划衔接检查结果直接决定后续分析路径。

### 分流逻辑

```
Step 0.5.4 计划衔接检查结果
│
├─ 有持仓（计划已触发）→ 路径D：Step 1 + Step 7（跳过 Step 2-6）
├─ 有计划且完全有效 → 路径A1：Step 1 快速更新（跳过 Step 2-6）
├─ 有计划需调整 → 路径A2：Step 1+3 调参（跳过 Step 2/4/5）
├─ 有计划已失效 → 路径B：完整 Step 1-6，生成新计划
└─ 无活跃计划 → 路径C：完整 Step 1-6，生成新计划
```

### 核心原则

1. **计划优先**：已有有效计划时，优先管理计划，不生成新计划
2. **最小必要分析**：根据计划状态决定分析深度
3. **计划一致性**：只有明确标记"失效"后才能生成新计划

### 各路径写入规则（先执行后写入）

| 路径 | 分析后写入 |
|------|-----------|
| D | market_state.md + logs/analyses/ + order_log.md（如有调整/平仓） |
| A1 | market_state.md（仅更新价格）+ logs/analyses/（简短记录） |
| A2 | market_state.md（更新调整参数）+ logs/analyses/（调整原因） |
| B | market_state.md（标记旧计划失效+写入新计划）+ logs/analyses/（完整归档） |
| C | market_state.md（写入新计划）+ logs/analyses/（完整归档） |
