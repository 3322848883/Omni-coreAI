# 取数覆盖度闸门：从「调过就算过」到「缺周期就点名」

日期：2026-10-26 19:30 · 提交 `b9683dd` · 分支 `fix/size-chain`

---

## 一、问题：`data_checked` 判不了「够不够」

原来的防偷懒只有一条防线（`loop.py:_chat_with_tools`）：

> **全程一次工具都没调** → 强制重试一次。

而 `data_checked = bool(工具名交集非空)` —— **调 1 次就算过**。

实测（`martin-grid-paper`，同一天 4 轮）：

| 轮次 | 工具调用 | data_checked | 覆盖 |
|---|---|---|---|
| r3 | 8 次（map 5 + events 3） | True | 接近完整 |
| r4 | **4 次**（map 15m/1h/4h + events 15m） | True | 缺 1d |
| r5 | **4 次** | True | 缺 1d |
| 人格要求 | 5 周期 × (map + events) = **10 次** | — | — |

后果不是崩，而是**决策依据造假**：模型从没查过日线，却写「马 3 落在日线结构位」——
而马 3 是 −6% 的深层加码，它的位置合法性完全依赖日线/4h 结构。

---

## 二、修法：两级防线 + 底线可配

### 1. `PlanRunner._data_coverage()`

按 `strategist.tools.required_coverage` 统计「工具 × 周期」覆盖，返回 `(covered, missing)`。
周期归一化（去空格 + 小写），没有 `tf` 的调用（`skill` / `skill_ref`）不充数。

```yaml
strategist:
  tools:
    required_coverage:
      smc_map: ["15m", "1h", "4h", "1d"]
      smc_events: ["15m", "1h"]
```

**缺省不配 = 不检查**（零行为变化）。

### 2. `_chat_with_tools` 第二级重试

| 情形 | 动作 |
|---|---|
| 一次工具都没调 | 重试一次（原逻辑） |
| **缺必需周期** | **重试一次**，把缺的项点名，并说明 `smc_map` / `smc_events` 的 `premium_discount` 口径不同、不能互替 |
| 重试后仍缺 | **放行** + 日志留痕（不拒单：整轮作废的代价远大于多查一次数据） |
| 重试拿回空串 | 退回第一次输出（不让整轮变成空计划） |

只重试一次、不递归。

### 3. `tool_usage_summary.coverage_missing`

**只在配了 `required_coverage` 时才加这个键** —— 未配置的 bot 输出形状逐字不变
（`tests/test_symbol_observability.py::test_old_fields_shape_unchanged` 精确断言了旧字段集合）。

### 4. 配置

`martin-grid.yaml`（live）与 `martin-grid-paper.yaml` 都加同一份 `required_coverage`。

> 设计意图：**引擎是底线（6 次），人格仍是目标（10 次）**。人格第八节「5 周期各一次」没动 ——
> 引擎只保证「不会在信息不足时静默出计划」，不替代人格的完整性要求。

## 三、验证

### 单元测试 `tests/test_data_coverage.py`（12 条，全绿）

| 组 | 覆盖 |
|---|---|
| 覆盖判定（5） | 未配置不拦 / 齐全为净 / 缺 1d+events:1h 点名 / 大小写空格归一 / 无 tf 不充数 |
| 形状契约（3） | 未配置时 keys 精确等于旧集合 / 配置时 `coverage_missing` 准确 / `cfg` 无 `tools` 属性不炸 |
| 重试（4） | 缺项重试一次且点名 / 齐全不重试 / 未配置不重试 / 重试空串退回第一次 |

### 实测（同一天后续两轮）

| 轮次 | 工具调用 | 是否重试 | `coverage_missing` |
|---|---|---|---|
| r6 | 首轮 4 次 → 补查 1h/1d/events:1h → **7 次** | 触发一次 | `[]` |
| r7 | **一次 8 次**（map 15m/1h/4h/1d/5m + events 15m/1h/4h） | 未触发 | `[]` |

r6 的 `reasoning` 开头就是证据：

> 「**补查 1h/1d 结构**：1h 价在 discount 但 swing bear，**1d swing bull**。」

这是它此前从没拿到过的信息（之前只查 15m/1h/4h）。

## 四、过程中踩的两个坑（都已修）

1. **无条件往 `tool_usage_summary` 加键** → 破坏「旧字段形状不变」契约，实测 **6 error + 1 fail**
   （`test_old_fields_shape_unchanged` 断言 `set(s)` 精确相等）。→ 改成「配了才加」。
2. **`getattr(self.cfg, ...)` 对 `PlanRunner.__new__(PlanRunner)` 构造的 runner 抛 AttributeError**
   （`test_observability::test_long_content_survives` 这样构造，没有 `cfg`）。→ 改成
   `getattr(getattr(self, "cfg", None), "tools", None)`。
