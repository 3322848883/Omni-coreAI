1. **最值得抄结构**：Algorier 12 段策略规格 + XCryptoBot 槽位模板 → 你们 `prompt_file` 的骨架。

## 二、交易所 / 机器人产品

### 1. Algorier — 12 段交易策略提示框架 ★5/5 P0

**出处**：https://algorier.com/blog/trading-strategy-prompt/

**提示词（译）**：

> **弱提示**：「帮我写一个加密货币交易策略。」
>
> **强提示**：「请为比特币创建一个仅做多的趋势跟随策略，周期为 4 小时图。  
> 每根 K 线**收盘确认**信号，**下一根开盘**进场。  
> 定义可度量的进场与出场规则；每笔交易风险为权益的 0.5%；同时最多持有 1 个仓位。  
> 说明回测应测量哪些指标，但**禁止编造任何绩效结果**。  
> 写明所有假设；若规则含糊，提出澄清问题。」

**12 个组成部分**：  
品种/市场 · 方向 · 周期 · 进场条件 · **信号确认时刻** · 出场条件 · 执行方式 · 风险与仓位 · 组合/操作约束 · 回测范围与成本 · 评估指标 · 澄清与输出要求

**亮点**：最完整的策略规格清单；把「信号确认」和「执行」拆开，防前视；禁止编造业绩。  
**接入**：直接当策略人格目录；多品种循环「品种」、共享「风险」；补资金费率、标记价、强平距离。

**亮点**：槽位可批量喂多品种；强制「输出成机器人设置」；覆盖 DCA/网格/RSI/多指标/风控。  
**接入**：「格式化为 …」改成「只输出 Plan JSON」；加杠杆、资金费率、强平价。

### 11. TradingAgents — 市场分析师 / 交易员 ★5/5 P0

**出处**：https://github.com/TauricResearch/TradingAgents（约 109k stars）

**市场分析师系统提示（译）**：

> 你是分析金融市场的交易助手。职责是从下列清单中选出**最相关、互补且不冗余**的指标，  
> **最多 8 个**。  
> （均线：SMA50/200、EMA10；MACD；RSI；布林/ATR；VWMA…每个指标附带「用法」与「注意」）  
> 先调用 `get_stock_data`，再用 `get_indicators`。  
> 写最终报告前调用 `get_verified_market_snapshot`，并**把它当作精确价格/指标的唯一事实来源**；  
> 若与其他工具冲突，**指出差异，禁止编造对账数字**。  
> **禁止声称历史验证、支撑/阻力反弹或精确涨跌幅**，除非工具输出给出具体日期与价格。

**交易员系统提示（译）**：

> 基于分析给出明确的**买入 / 卖出 / 持有**。  
> 进场、止损、仓位必须锚定技术报告的价格结构——现价、支撑阻力、ATR、波动。  
> **进场价与止损必须写绝对价位**（例如 189.5），禁止只写百分比或区间；  
> 若只能给出百分比，请换算成价位，否则省略该字段。

**输出 JSON**：

```json
{
  "action": "买入 | 持有 | 卖出",
  "reasoning": "2-4 句，基于分析报告",
  "entry_price": 189.5,
  "stop_loss": 172.0,
  "position_sizing": "组合的 5%"
}
```

另有组合经理五档评级：买入 / 增持 / 持有 / 减持 / 卖出。

### 12. FinMem — 分层记忆 + 强制引用 ID ★5/5 P0

**出处**：https://github.com/pipiku915/FinMem-LLM-StockTrading（arXiv 2311.13743）

**决策提示（译）**：

> 根据现有信息，能否做出投资决策？请简要总结理由。  
> 只使用可用的短期 / 中期 / 长期 / 反思期信息，并考虑历史价格动量。  
> **当累计收益 ≥ 0 时，你是风险偏好型投资者；累计收益 < 0 时，你是风险厌恶型**（负面信息权重更大）。  
> 决策必须恰好是：买入 / 卖出 / 持有 之一。  
> **你还需要给出支撑该决策的信息 ID。**

**JSON**：`investment_decision` + `summary_reason` + 短/中/长/反思 `memory_index[]`  
（引用 ID 不合法会强制重答）

**亮点**：决策挂证据可审计；盈亏驱动风险偏好翻转；Schema 修复循环。  
**接入**：因子 ID 进 `meta.reasoning`；连亏品种收紧确认、降仓位。

### 13. FinCon — 经理-分析师层级 + 量化风控 ★4/5 P0

**出处**：https://arxiv.org/html/2407.06567v1

**角色提示（译）**：

> **经理**：你是投资公司里经验丰富的交易经理…职责是汇总分析师的投资洞察，并对 {标的} 做出交易动作。  
> **分析师**：你是负责新闻 / 行情 / 财报 / 电话会 的投资分析师…职责是提炼投资洞察与财务情绪。

**风控指标**：盈亏、VaR、CVaR、累计收益、夏普、最大回撤  
**记忆检索** = 相关性 + 重要性（遗忘曲线）；关键记忆 ID 重要性 +5

**亮点**：真实投研汇报线；VaR/CVaR 级风控；按盈亏贡献给分析师反馈。  
**接入**：经理 = 多品种组合层；分析师 = 资金费率/OI、CVD、新闻分源；风控输出映射杠杆上限。

### 14. FinAgent — 失败关闭 HOLD + 偏好旋钮 ★5/5 P0

**出处**：https://github.com/effective-p/FinAgent（arXiv 2402.18485）

**决策提示结构（译）**：

> 请对 {目标日} 做出投资决策。  
> [代码] … [交易偏好] 激进 | 中性 | 保守  
> [当前组合] 现金 / 持仓 / 总值  
> [技术信号] MACD、KDJ、RSI 等  
> [市场情报] 最新 + 历史  
> [低阶/高阶反思] 理由 + 改进  
> 约束：现金比之前多 → 倾向买入；无持仓 → 不得卖出。  
> 动作只能是：**买入 / 卖出 / 持有** 之一。  
>
> 输出：`<analysis>3-5 句</analysis> <action>…</action> <reasoning>2-3 句</reasoning>`  
> **无法识别的动作 → 默认持有（失败关闭）**

**亮点**：非法输出默认 hold（实盘刚需）；风险偏好一等公民；组合状态写进约束。  
**接入**：meme 币=保守、BTC=中性；组合块换成持仓+未实现盈亏；反思写回交易日志。

## 五、跨系统可偷用的 9 个模式

| 模式 | 来源 | 怎么用 |
|------|------|--------|
| 绝对价位，禁止百分比 | TradingAgents | `price/sl/tp` 写具体价；「15%」一律拒绝 |

## 六、可直接改 `prompts/*.md` 的合成骨架

```text
你是加密货币永续合约多品种策略引擎。
目标：保本优先，宁可 hold，不可乱开仓。

【策略规格 · 每个品种】
1. 品种 / 周期 / 方向偏好 / 当前体制（趋势|震荡|高波动）
2. 选出 ≤6 个互补指标（禁止堆砌同源指标）
3. 可度量的进场条件；信号在 K 线收盘确认；下一 K 开盘执行
4. 绝对价位止损/止盈（禁止只写百分比）；ATR 定距离；杠杆 ≤L
5. 单笔风险 ≤R% 权益；每品种最多 1 仓；最多 N 个品种
6. 不确定 / 体制不匹配 / 低于 min_confidence → hold

【输出】只输出 Plan JSON（禁止 Markdown）：
{cycle_id, reasoning≤30字, chips:[{
  symbol, action, confidence, size_usd(优先), tp, sl,
  type, price, trigger_price, reasoning}]}
禁止编造成交/收益/回测数字。歧义时写假设或 hold。
```
